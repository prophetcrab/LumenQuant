# 迭代记录 C44：归档操作的前端反馈

## 动机

C43 修了后端问题：归档账户后实例仍在交易。修完之后，前端还有两处描述与事实不符。

## 缺陷一：归档按钮不告知后果

账户卡片底部的说明是：

> 出入金只影响模拟现金余额，不改变已实现盈亏；归档后禁止下单与入金，历史数据仍可查询。

这句话在 C43 之后**不完整了**：归档现在还会停止该账户下所有自动运行实例。
用户点"归档账户"以为只是冻结出入金，实际上自动策略也停了——
如果正在跑一个重要策略，这个副作用需要事先知道。

修法：说明文字补上"并停止该账户下所有自动运行实例"。

## 缺陷二：一键归档，没有确认

原来的按钮直接 `onClick={() => toggleStatus.mutate(...)}`，
点一下就归档，没有确认。归档是不可逆地改变账户可用状态的破坏性操作
（虽然可以恢复，但期间实例已停、下单已拒）。

修法：改用应用内确认对话框，明确列出三条后果：

1. **禁止下单与入金**
2. **所有运行中的自动运行实例会被停止**
3. 已有持仓不会自动平仓；历史数据仍可查；恢复后需手动重启实例

确认按钮用 `danger` 样式。

### 为什么不用 `window.confirm`

第一版用了原生 `window.confirm`，结果**阻塞了浏览器自动化**：
`confirm()` 是同步模态，Playwright 的调用在等待页面响应时超时。
这不只是测试问题——任何在自动化环境（CI、脚本、无障碍工具）里操作这个页面的人都会卡住。

应用内 `<Modal>` 不阻塞事件循环，与项目里其他确认（入金/出金、创建实例）保持一致。

### 恢复的提示

恢复账户成功后提示"自动运行实例需要手动重新启动"。
恢复账户不等于恢复自动化——这是 C43 的刻意设计，需要让用户知道。

## 后续

- 恢复账户时没有确认（只有归档有）。恢复是"解锁"，风险较低，可以接受。
- 归档一个有持仓的账户时，可以考虑在确认框里显示持仓数量与市值，
  让用户判断是否需要先平仓。
