# 迭代记录 C90：A 股选股（全市场筛选）

## 背景

此前平台只能对**已登记**的 8 只 A 股做图表、回测和交易。用户问的是"帮我找股票"，
系统却只能回答"我可以分析你已有的这些"。这一轮补上全市场选股。

## 数据源：新浪行情榜单

东财 `push2.eastmoney.com/api/qt/clist/get` 是最常见的全市场接口，本机实测
**首次请求成功、后续一律连接被断**（`RemoteProtocolError`，换 http/备用域名/
加 UA 与 Referer 均无效），属于 IP 级限流。因此改用新浪：

```
https://vip.stock.finance.sina.com.cn/quotes_service/api/json_v2.php/
Market_Center.getHQNodeData?page=N&num=100&sort=...&node=hs_a
```

返回字段覆盖筛选所需的全部维度：价格、涨跌幅、成交额、换手率、PE、PB、
总市值、流通市值。`node=hs_a` 一次即覆盖沪深北全部 A 股（实测 5,573 只）。

### 单位归一化

新浪给的是 **成交额（元）** 与 **市值（万元）**，而界面上用"亿元"最自然。
转换只做一次，在 `_normalise` 里完成，后续所有比较都用同一单位：

```python
amount_yi = amount / 1_0000_0000      # 元 -> 亿
market_cap_yi = mktcap / 1_0000       # 万元 -> 亿
```

这一步错了不会报错，只会让数字差 10,000 倍——测试里专门钉住了换算。

## 三个必须处理的数据陷阱

### 1. 停牌股 `trade = 0`

停牌标的返回价格 0、成交额 0。如果不剔除，"股价低于 10 元"这类筛选会把它
当成"便宜"而排在前面。归一化阶段直接丢弃。

### 2. 亏损股没有 PE

新浪对亏损公司返回空字符串或 0。若按 `value <= 20` 判，"市盈率低于 20"的
筛选会把**所有亏损股**当成最便宜的标的。代码里显式排除：

```python
if (f.pe_min is not None or f.pe_max is not None) and candidate["pe"] is None:
    return False
```

### 3. 缺失值排序

即使不加 PE 条件，按 PE 排序时缺值也要稳定地排在末尾——降序排序若直接反转
整个列表，None 会跑到最前面。实现上把有值/无值分组，各自排序后拼接。

## 性能：47 秒 → 10 秒

第一版顺序拉 56 页，全市场耗时 **47.6 秒**。用户改一个滑块就要等这么久，
不可接受。改为 6 路并发（每页失败重试一次，仍失败则跳过并告警）：

```
顺序:  47.6s
并发:   9.5s
```

再叠加 60 秒的快照缓存：同一分钟内反复调整条件不会重复拉取。
缓存刻意做得短——盘中价格一直在变，1 分钟的陈旧数据已经是容忍上限。

## 六个预设方案

预设不是为了省点击，而是把"值得看的理由"固化下来：

| 预设 | 条件 |
|---|---|
| 强势突破 | 涨 3%–9.5%、换手 3%–15%、成交额 ≥2 亿 |
| 超跌反弹 | 跌 9%–3%、换手 ≥5%、成交额 ≥1 亿 |
| 放量活跃 | 成交额 ≥5 亿、换手 ≥8% |
| 低估值蓝筹 | 市值 ≥300 亿、PE 5–20、PB 0.5–3 |
| 小盘活跃 | 市值 30–150 亿、换手 5%–25% |
| 主板稳健 | 仅主板、市值 ≥100 亿、涨跌 −2%–5% |

阈值都取得足够宽，正常交易日能产出几十到几百个候选——太窄（0 只）或太宽
（几千只）的筛选教不会任何东西。

## 从"看到"到"能用"

选股结果如果不能立刻被图表、回测、交易使用，就只是一个静态列表。
`POST /screener/add-symbol` 把标的写入本地目录（板块从代码前缀推断），
之后就能用现有的同步/回测/下单流程。前端每行一个「加入标的」按钮。

刻意**不**在这里顺带拉历史数据：同步是另一个明确的动作，混进来会让点击
按钮等待十几秒且失败原因难以区分。

## 顺带修掉的一个测试缺陷

C87 的两个 `prev_close` 滚动测试把"今天"硬编码成 `date(2026, 10, 23)`。
它们在 10-22 通过，到 10-23 就失败了——因为种子数据本身已包含当天，
"最后一天收盘"变成了另一根 bar。

改为从数据里取最新一根日线，`target = day_key(newest.open_time) + 1 天`，
测试不再依赖执行当天的日期。

## 已知限制

1. **只有实时快照，没有历史**：筛选基于当前时点。想看"昨天符合条件的有哪些"
   需要另建快照存档，本轮未做。
2. **不筛财务指标**：营收增速、ROE、毛利率等需要另一类数据源，当前只有行情与估值。
3. **单次快照 60 秒缓存**：盘中两次筛选间隔小于 1 分钟时看到的是同一批数据；
   需要强制刷新可传 `force=true`。
4. **分页上限 70 页**（约 7,000 只）：当前全市场 5,573 只，余量足够；若市场
   大幅扩容需要调高 `MAX_PAGES`。
