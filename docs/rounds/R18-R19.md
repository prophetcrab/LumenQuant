# R18–R19 安全加固与稳定化

## R18 需求设计
默认零摩擦，开启后可对外：
- 可选 Bearer 令牌（`LQ_AUTH_ENABLED` + `LQ_AUTH_TOKEN`），`/health` 与文档保持公开；
- 固定窗口限流（默认 600 次/分钟/IP，`RATE_LIMIT_PER_MINUTE` 可调）；
- 实盘账户下单需 `X-Live-Confirm: true`（与服务端开关构成双保险）；
- 令牌比较使用 `hmac.compare_digest`，避免时序侧信道。

## R18 代码编写
- `core/security.py`：`AuthMiddleware`、`RateLimitMiddleware`。
- `trading/router.py`：实盘下单确认头。
- 测试 5 例：默认关闭可访问、令牌校验通过/失败、开启但未配置令牌则全拒、限流 429 且带 Retry-After、实盘缺确认头 403。

## R18 审查
1. 认证开启但令牌为空必须**拒绝**而不是放行（已处理）。
2. OPTIONS 预检放行，避免 CORS 与认证互相卡死。
3. 限流按 IP 计，单用户本地不会误伤（600/min 远高于前端轮询）。
4. 限流为进程内状态，多进程部署会各算各的 → 文档明确单机假设。

## R19 压力测试

### 系统混合负载（`tests/stress/system_load.py`）
新账户、100 笔并发市价单 + 240 次读查询：

| 指标 | 结果 |
|---|---|
| 下单 P50 / P95 / max | 25ms / 196ms / 1004ms |
| 读查询 P50 / P95 / max | 21ms / 98ms / 124ms |
| 读查询错误 | 0 |
| 权益对账（现金+持仓市值=权益） | ✅ 差值 0.0 |
| 账本对账（流水求和=现金） | ✅ 差值 0.0000002 |
| 成交覆盖（成交数 ≥ 已成交订单数） | ✅ 90 = 90 |

被拒绝的 10 笔均为“卖出无持仓”，属 R12 风控的预期拒绝，不是故障。

### 策略与回测吞吐（`tests/stress/strategy_load.py`）
2 标的 × 9 策略 × 3 轮，2000 根 1h K 线：54 次回测，P50 8.2ms、P95 74.4ms、总耗时 1.54s。

### 限流验证
设置 3 次/分钟后第 4 次请求返回 429 且带 `Retry-After`；正常配置下 100 笔并发下单未触发 IP 限流，仅触发账户级“每分钟 120 单”，符合设计。
