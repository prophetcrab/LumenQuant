## 缺陷一：总览页"净投入"硬编码美元

A 股账户的总览页：

```
账户权益  ¥999,351.87
可用现金  ¥982,487.87
净投入    $1.00M          ← 其他都是 ¥
```

根因和 C42 修过的是同一类问题，但位置不同——这里是 `compact()` 前面
直接拼了一个 `$`：

```tsx
meta={<span className="muted">净投入 ${compact(data?.net_contributions)}</span>}
```

改为走 `cash()`，与其他金额一致。

**这类问题的反复出现说明**：只要还有地方手写货币符号，就会继续错。
C42 修的是图表 formatter，这一轮修的是文本标签，下次可能还有别的地方。

## 缺陷二："24h 成交额"实际上是成交量

市场页显示：

```
24h 成交额  1.62M
```

但后端 `volume_24h` 是 K 线 `volume` 字段的累加：

```python
volume_24h = sum(p.volume for p in window)
```

`volume` 是**基础资产的成交量**（股数或币数），不是以计价货币计的金额。
要算成交额，需要 `volume × price`（更准确地说是逐笔或逐根的均价加权）。

A 股用户看到"成交额 1.62M"会以为是 162 万元；实际是 162 万股。
在茅台这种高价股上，两者差三个数量级。

修法：标签改为"24h 成交量"，并按市场标注单位：

- A 股 → `股`
- 加密 → 去掉 `USDT` 后缀的币种名（`BTC`）

## 设计取舍

- **为什么不干脆算出真实成交额**：需要逐根 `volume × close` 再求和，
  数据是有的，但 A 股的 `volume` 单位在腾讯接口里是"手"还是"股"
  需要逐个数据源核实——腾讯日线的 volume 是手还是股，不同接口并不一致。
  在核实清楚之前，标注成"成交量"是诚实的做法。
- **为什么单位写在值后面而不是标签里**：`1.62M 股` 比"成交量（股）：1.62M"
  更紧凑，且单位紧贴数字不易误读。
- **为什么不在 `compact()` 里加单位**：`compact()` 也用于非数量的场景，
  把单位语义塞进去会让它变成一个猜上下文的函数。
