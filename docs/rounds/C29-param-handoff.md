# 迭代记录 C29：策略参数一键带到回测

## 动机

C28 盘点时记下的第一个体验断点：策略库和回测是两个独立页面。
用户在策略库里把参数调到满意，想验证长期表现，必须切到回测页再把这些数字手抄一遍。
抄错参数在回测里是灾难性的——你以为在验证 A，实际验证的是 B。

## 实现

**策略库侧（`StrategiesPage.tsx`）**

在信号预览旁边加"带去回测"按钮，把当前上下文序列化进 URL：

```
/backtest?strategy=sma_cross&symbol=600036.SH&timeframe=1d&params={"fast":7,"slow":55,...}
```

参数经 `buildParams()` 处理，保持 schema 声明的类型（数字仍是数字、布尔仍是布尔），
而不是把表单里的字符串原样塞进 URL。

**回测页侧（`BacktestPage.tsx`）**

- 在首次渲染（useState 初始化）之前读取 query，策略、标的、周期直接作为 state 初值，
  页面打开即是目标状态，没有"先闪一下默认值"的过程。
- 参数用 `{ ...schema 默认值, ...传进来的值 }` 合并：新策略新增的字段有默认值兜底，
  传入的字段优先。
- **消费后清空 URL**：`setSearchParams({}, { replace: true })`，避免刷新或后续切换策略时
  把旧参数重新盖回去。

## 踩到的坑：StrictMode 吃掉参数

第一版把 handoff 放在 `useEffect` 里消费（读 ref → setParams → 置空 ref）。
结果标的和周期传过来了，**参数却回落到默认值**。

原因是 React 严格模式下副作用会执行两遍：第一遍正确合并了参数并清空 ref，
第二遍进入"没有 handoff"分支，用 `initialParams(meta)` 把刚合并好的参数覆盖掉。
标的/周期没有暴露问题，是因为它们由 `useState` 初值决定，不经过这个 effect。

修法有两条：

1. 参数也改成 `useState` 初值（`handoff.current?.params ?? {}`），effect 只负责补 schema 默认值；
2. 合并逻辑做成幂等：用 `metaKeyRef` 区分"首次/同一策略"与"真的切换了策略"，
   前者合并、后者重置。

清空 URL 的 effect 也加了 `handoff.current = null` 守卫，否则依赖数组里的
`setSearchParams` 变化会让它反复执行。

## 设计取舍

- **为什么用 URL 而不是全局状态 / localStorage**：URL 可分享、可刷新、可回退，
  而且不需要引入额外状态库。参数是 JSON，长度可控（单策略最多几个字段）。
- **为什么参数用 JSON 而不是逐字段 query**：逐字段需要前端知道每套策略的字段名，
  新增策略就得改传参代码；JSON 与 schema 无关，天然可扩展。
- **为什么打开后清空 URL**：回测页刷新后应保持用户当前编辑，而不是回退到进入时的参数。
  这是"交接一次"的语义，不是"持续绑定"。
