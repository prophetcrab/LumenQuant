# 迭代记录 C18：复权口径不一致导致的虚假涨幅

## 现象

真实数据接入后，A 股页面出现不可能的数字：

```
000858.SZ 五粮液   213.21   +192.97%   涨停
300750.SZ 宁德时代 110.18    -58.74%   跌停
600519.SH 贵州茅台 2497.25   +88.48%   涨停
```

八只股票全部被标记为涨停或跌停，涨幅从 -70% 到 +192%。

## 定位

对比实时报价与数据库中的日线收盘：

| 代码 | 实时报价 | 库里前收 | 库里倒数第二根 |
|---|---|---|---|
| 000001.SZ | 7.38 | 11.65 | 11.44 |
| 000858.SZ | 213.21 | 72.82 | 72.85 |
| 600036.SH | 12.61 | 43.05 | 42.52 |

**同一只股票，两个价格体系**。实时报价与库里的前复权价差了 2–6 倍。

根因：我用了前复权接口 `fqkline/get?...,qfq`（返回 `qfqday`），
而实时报价 `qt.gtimg.cn` 返回的是**不复权**价格。

前复权会把历史价格按除权比例缩放，所以长期分红送股的标的
（如平安银行、五粮液）复权价与现价差异可达数倍。

于是：
- 快照涨跌 = (不复权现价 / 前复权昨收 - 1) → 虚假的 ±70%；
- 涨跌停区间基于前复权昨收 → 现价必然落在区间外 → 全部显示涨停/跌停。

## 修复

改用不复权日线接口：

```
https://web.ifzq.gtimg.cn/appstock/app/kline/kline?param=sh600519,day,,,N,
```

（注意是 `kline/kline` 而非 `fqkline/get`，且复权参数留空。）

修复后：

```
000001.SZ 平安银行  11.40   -0.35%   [10.30, 12.58]
000858.SZ 五粮液    73.15   +0.41%   [65.56, 80.14]
600519.SH 贵州茅台 1323.58  -0.62%   [1198.69, 1465.07]
688981.SH 中芯国际 101.76   -0.22%   [81.58, 122.38]
```

涨幅落在合理区间，无一被误标为涨跌停。

## 新增测试（2 项）

1. `test_daily_endpoint_uses_unadjusted_series`
   - 断言请求 URL 不含 `fqkline`、不含 `qfq`；
   - 这是防回归的关键：只要有人把接口改回复权，测试立刻失败。
2. `test_quote_and_daily_share_the_same_price_scale`
   - 断言最新日线收盘与实时报价的相对误差 < 0.1%；
   - 这是一条**跨接口不变量**，能捕获任何单位/复权口径漂移。

## 教训

这是一次典型的"每条链路单独看都正常，拼起来全错"：

- 数据源解析测试通过（价格确实是接口返回的）；
- 同步测试通过（数据确实入库了）；
- 报价测试通过（现价确实实时）；
- 只有**把两者放在一起**才发现口径不一致。

所以多源数据接入必须显式声明并校验**同名量的口径**：
复权方式、币种、单位、时间基准。任何一项不一致，聚合结果就失去意义。

当前实现的选择：**全系统统一使用不复权价**，因为：
1. 实时报价只能拿到不复权价；
2. 涨跌停计算必须基于不复权价（交易所就是这么算的）；
3. 回测若需要复权，应在导入时单独提供复权序列，而不是混在实时链路里。

这一点已写入 `docs/delivery/cn-data-source.md`。
