# 迭代记录 C31：多回测组合分析

## 动机

回测页到此为止有三个视角：单次回测、参数优化、滚动验证，全部都是**一个策略、一个标的**。
但真实决策不是这样做的——"这几个策略一起上，会不会其实是同一个赌注？"这个问题
任何单个回测都回答不了。

已有的三份工具做的是同一件事的不同侧面：优化器找最佳参数、滚动验证查稳定性、
基准对比看是否跑赢指数。缺的是**跨回测的横向对比**。

## 后端：只读的组合分析

`POST /api/backtests/portfolio`

```json
{ "run_ids": ["...", "..."], "weights": [4, 1], "initial_capital": 100000 }
```

分析**完全基于已保存的权益曲线**，不重跑回测。这一点是刻意的：
用户刚看过单次结果，组合数字如果是重新跑出来的，哪怕差 0.01% 也会让人怀疑前面的是不是假的。

### 对齐

- 取所有回测时间戳的**交集**，只在公共区间上合并
- 每个成分按自己的权重获得 `capital × weight` 的名义资金，再以重叠区间首根为基准缩放
- 合并曲线 = 各成分曲线的**和**（不是加权平均的二次缩放），所以费率和仓位逻辑保持原样

### 指标

| 区块 | 内容 |
|---|---|
| `metrics` | 合并权益曲线的收益、Sharpe、Sortino、Calmar、波动、回撤（交易类指标置 `null`，因为每段有自己的交易列表） |
| `components` | 每个成分的权重、资金、区间内收益、波动、回撤、对齐/总 K 线数 |
| `correlation` | 逐根收益率的 N×N 相关矩阵 |
| `diversification` | 加权波动 vs 实际波动、比值、分散收益百分比 |
| `warnings` | 高相关、区间覆盖不足、标的/策略单一致 |

### 拒绝的情况

- 少于 2 个或多于 8 个
- 周期不一致 —— 不同周期无法逐根对齐
- 市场不一致 —— 加密 24 小时与 A 股 4 小时交易时段不同
- 重叠不足 50 根
- 重复的 run_id、不存在的 run_id

每种都给出**具体数字或具体原因**，而不是笼统的 "invalid request"。

## 前端：第四个标签

回测页新增"组合分析"标签：可勾选的回测列表 + 权重输入 + 初始资金。

结果区：

1. **四张指标卡**：组合收益、Sharpe、最大回撤、分散效果
2. **黄色告警条**：相关性过高、区间覆盖不足等
3. **组合权益曲线**：复用单次回测的图表组件
4. **成分表**：权重、资金、区间内收益、波动、回撤
5. **相关性矩阵**：红/绿热力图，绿=负相关（分散有效），红=同涨同跌

## 踩到的问题

1. **两个同类回测标签完全相同**。都跑 `sma_cross · 600036.SH` 时矩阵行头一样，
   根本看不出谁是谁。改成当裸标签重复时追加 `#run_id 前 4 位`。
   前端也从"只取 ` · ` 前一段"改成保留这个后缀——原来那个截断正好把区分信息切掉了。
2. **回撤和波动被加了 "+" 号**。共用 `pct()` 是给涨跌设计的，而回撤是量值不是方向。
   组合面板单独用 `mag()`。
3. **`price()` 不支持第二参数**，误传币种会编译失败——直接调用单参数版本。

## 后续

- 组合目前是"事后合并"，还没有直接把组合配置落成一个可运行的组合实例。
- 相关性基于同一时间窗的逐根收益；不同策略的持仓周期差异较大时，
  逐根相关会低估真实的相关性，后续可加基于交易区间的相关。
