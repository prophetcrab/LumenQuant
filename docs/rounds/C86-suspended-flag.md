# 迭代记录 C86：停牌状态没有随行情一起下发

## 排查过程

先确认停牌标记的实际效力：

```
买入 100 股              → 201 filled
标记停牌                 → suspended=True
停牌中平仓               → 409 "600519.SH 停牌中，无法交易"    ✓
持仓仍在                 → 100 股                            ✓
```

**交易拦截是正确的**：下单、撮合、平仓三条路径都拒绝停牌标的。
持仓估值也正确——停牌期间的权益仍按最后一个成交价计（`1637.21`），
没有归零、也没有跳到无法解释的数字。

问题在**信息的可见性**。

## 缺陷：`Snapshot` 没有 `suspended` 字段

停牌股票的价格就是它最后一个成交价，所以只看 `price` 和一个正常标的没有区别：

```json
{"symbol": "600519.SH", "price": 1637.21, "change_24h_pct": 0.0,
 "limit_up": 1800.93, "limit_down": 1473.49}
```

要判断它是否停牌，调用方必须再去查 `/api/cn/symbols`（那是另一个接口、
另一个数据结构）。后果：

- **AI 助手**会把停牌价描述成"当前价格"，用户以为还能交易；
- **行情快照接口**的消费方（含未来的策略逻辑）无法区分"停牌"与"今天没涨跌"；
- 前端两处页面各自持有 `SymbolInfo` 才能显示停牌徽章，属于重复取数。

## 修复

`Snapshot` 增加 `suspended: bool = False`，两个 A 股构造点都填上
（正常路径与"无 K 线但有昨收"的回退路径）。

同时把该字段加入助手工具的 `_snapshot_row`：一个模型若只看到价格，
会自然地把它当成可交易价格来描述。

```json
{"symbol": "600519.SH", "market": "cn_stock", "currency": "CNY",
 "price": 1637.21, "change_24h_pct": 0.0, "change_label": "较昨收",
 "suspended": true}
```

## 验证

| 断言 | 结果 |
|---|---|
| 未停牌时 `suspended=False` | ✓ |
| 标记停牌后 `suspended=True` | ✓ |
| 停牌时仍返回最后成交价（不是缺口） | price=50.0 |
| 停牌时涨跌停仍可计算 | ±10% → 55.0 |

集成验证：`/api/market/snapshot` 与 `/api/market/snapshots` 都带上
`suspended: true`。

还原（移除两个构造点的字段）后测试失败。

## 回归

- 前端 66 passed，`tsc` 干净，构建通过
（新增必填字段让两处测试 fixture 缺字段，已补齐——这正是类型系统该起的作用）

## 已知限制

1. **加密市场恒为 `false`**：没有停牌概念。
2. **不表达停牌原因与起止时间**：只表示"当前不可交易"。
3. **停牌期间不更新日线**：这是正确的（无成交即无新 K 线），但意味着
   停牌跨越多个交易日时，日线序列会出现缺口——数据质量面板会如实报告。
