# 迭代记录 C25：滚动验证（Walk-Forward）

## 为什么需要它

C24 的网格搜索用单一 70/30 切分检验过拟合——只有**一个**样本外区间。
一个窗口的结果可以很好，也可能只是恰好落在有利行情里。

滚动验证把实验重复多次：

```
[--- 训练 1 ---][测试 1]
          [--- 训练 2 ---][测试 2]
                    [--- 训练 3 ---][测试 3]
```

每个窗口独立选参，再把参数**原样**用到紧随其后的样本外区间。
这样得到的是样本外收益的**分布**，而不是一个点。

## 实现

`app/modules/backtest/walkforward.py`：

| 组成 | 说明 |
|---|---|
| 窗口布局 | `total = train + test × windows`，测试窗口彼此不重叠 |
| 自动分段 | 默认约 3:1 训练/测试比，且测试段必须超过策略暖机 |
| 窗口自适应 | 数据放不下请求的窗口数时自动缩减，并在告警里说明 |
| 聚合 | 窗口胜率、均值/中位数/最差/最好、标准差、复合收益、平均衰减 |
| 告警 | 胜率 < 50%、最差 < -10%、平均衰减 > 10%、每窗口交易 < 3 笔、合成数据 |

关键设计：**报告最差窗口**。一个在某段行情里崩掉的策略，均值再好看也不稳健。

## 真实数据验证（招商银行，800 根日线，4 窗口请求）

```
完成 2 个窗口（数据只够 2 个，已自动缩减）
W1 训练 +22.33% → 样本外 +6.72%（3 笔）
W2 训练  +7.95% → 样本外 +3.61%（1 笔）
窗口胜率 100%，样本外均值 +5.16%，衰减 9.97%
```

前端实测（1200 根、4 窗口）：

```
完成 3 个窗口，跳过 1 个
W1 +13.63% → +12.75%
W3 +16.81% →  -0.36%
W4  +4.36% →  -0.04%
窗口胜率 33%，均值 +4.12%，衰减 +7.48%，累计 +12.30%
告警：仅 33% 的窗口样本外为正；每窗口仅 2.0 笔交易，统计意义不足
```

第三、四个窗口的样本外几乎归零——这正是滚动验证要暴露的：
**同一组参数在不同行情里失效**。单次 70/30 切分会给出"样本外 +7%"的乐观结论。

## 开发中修复的两个缺陷

### 1. 测试窗口短于策略暖机 → 窗口被静默跳过

第一次跑 4 窗口只完成 2 个，日志里是 `not enough candles for warmup`。
原因是自动分段只保证"≥ 60 根"，没有考虑策略本身需要 200 根均线暖机。

修复：分段时把 `暖机 + 10` 作为测试窗口下限，并据此重算布局。

### 2. 窗口布局算式错误

原写 `total = train + test × (windows - 1)`，实际布局是
`train + test × windows`（训练段之后紧接 windows 个测试段）。
这导致 800 根数据请求 4 窗口时错报"需要 1060 根"。

修复后校验：

```
total=800 w=4 -> train=560 test=60 need=800 fits=True
```

## 测试（12 项新增）

- 自动分段在各种 (total, windows) 下要么放得下、要么确认最小约束本身放不下；
- 窗口按顺序推进且测试段不重叠；
- `train_end == test_start`（衔接无空隙）；
- 衰减 = 训练收益 − 测试收益（定义一致性）；
- 聚合字段与窗口列表自洽；
- 拒绝过少数据、非法窗口数、空参数空间；
- 合成数据触发告警；
- 手动指定窗口尺寸被尊重。

全量：**276 passed**。

## 当前研究能力栈

| 层级 | 用途 | 是否防过拟合 |
|---|---|---|
| 单次回测 | 验证一组参数 | 否 |
| 网格搜索 | 找候选参数 | 部分（样本内外 + 盈利面 + 邻域） |
| 滚动验证 | 判断参数是否稳定 | 是（多窗口样本外分布） |

三者依次递进，但**都不能证明策略在未来有效**——它们只能帮你排除明显不靠谱的候选。
