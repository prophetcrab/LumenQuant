# 迭代记录 C61：多标的回测

## 动机

此前的回测一次只能跑一个标的。用户手上是一篮子股票时，只能逐个跑、再把结果
在脑子里拼起来——而那恰恰是最容易出错的地方：三个各自 +10% 的策略叠加起来
未必是 +10%，取决于它们何时入场、资金如何分配。

「组合分析」（C31）解决的是**多个已有回测**的合并，但它要求用户先手工跑完
N 次单标的回测。这一轮补上的是**一次调用跑完一篮子**。

## 实现

`POST /api/backtests/multi`

```json
{
  "strategy": "sma_cross",
  "symbols": ["BTCUSDT", "ETHUSDT", "SOLUSDT"],
  "timeframe": "1h",
  "bars": 300,
  "params": {"fast": 10, "slow": 30},
  "config": {"initial_capital": 300000},
  "weights": [2, 1, 1]        // 可选，省略则等权
}
```

### 执行模型

每个标的独立回测，资金按权重拆分：

```
sleeve_capital = total_capital × weight
```

**刻意不是**跨标的组合优化——各 sleeve 之间没有共享现金、没有相关性驱动的
仓位调整。理由：这套系统面向的是"一套规则跑一篮子"，而不是资产配置研究。
真正的组合优化需要协方差矩阵与再平衡策略，是另一个产品。

响应里用 `warnings` 说明这一点，并在数据可疑时提示。

### 对齐

只在**所有 sleeve 都有数据**的时间戳上求和。A 股与加密的交易时段不同，
所以混市场直接拒绝（422），而不是让交集悄悄缩水成几根 K 线。

每根 K 线的组合权益 = 各 sleeve 在该时刻的权益之和。

### 基准

等权买入持有同一篮子：每个 sleeve 的基准按自己的分配资金折算成货币值，
再求和。这样基准曲线与策略曲线单位一致，可以直接对比。

### 逐项指标

| 指标 | 来源 |
|---|---|
| 组合收益 / 回撤 / Sharpe / 波动 | 合并后的权益曲线 |
| 交易总数 | 各 sleeve 求和（不平均） |
| 胜率 / 盈亏比 / 平均持仓 | **置 null**——跨标的不具可比性 |
| 每个标的的收益 / 交易数 / 拦截原因 | 逐项列出 |

## 前端

回测页新增「多标的」标签：

1. 策略与周期选择器（面板自带，因为多标的视图不显示单标的的"目标"卡片）
2. K 线数量、组合总资金
3. 标的列表：勾选 + 权重输入，实时显示分配金额
4. 结果：四张指标卡、权益曲线（含等权基准虚线）、逐标的表现表

**市场锁定**：选中第一个标的后，列表只显示同市场的其余标的。
这不是替用户做决定，而是避免他配完整个表单才收到 422。

## 实测

浏览器里选 BTC/ETH/SOL 各 1 份权重，组合总资金 30 万：

```
组合收益      -1.06%      300 根共同 K 线
等权买入持有   +0.12%      同期同篮子
最大回撤       1.06%      持续 264 根
交易总数       14         各标的合计

BTCUSDT  33.3%  $100,000  -1.43%   6 笔
ETHUSDT  33.3%  $100,000  -1.75%   4 笔
SOLUSDT  33.3%  $100,000  +0.00%   4 笔
```

组合收益 -1.06% 落在三个 sleeve 的 -1.75% 与 0% 之间，符合"资金分散"的预期。

A 股篮子也验证过：`600036.SH + 601318.SH`，日线，返回 `currency=CNY`、
T+1 规则生效；`4h` 周期被正确拒绝。

## 设计取舍

- **为什么用独立 sleeve 而不是共享资金池**：共享资金池需要"谁先入场"的
  排序规则，而信号在同一根 K 线同时触发。独立拆分让每个标的的资金确定性，
  结果可解释。
- **为什么基准用等权买入持有**：这是"什么都不做"的自然对照。
  用单只标的做基准会偏袒那一个。
- **为什么胜率置 null 而不是算个总数**：合并不同标的的成交记录后，
  一笔 BTC 交易和一笔 ETH 交易混在一起算胜率，读者会误以为在评估一个策略。
- **为什么限制 12 个标的**：每次请求要跑 N 次完整回测。12 × 300 根约
  100ms，再往上会明显拖慢请求。需要更多可以分批。

## 后续

- 目前不落库：多标的回测结果不会出现在回测历史里。若要保存，需要新的表结构
  （一次运行对应多条 `BacktestRun` 加一条聚合记录）。
- 可以考虑"再平衡"选项：当前每个 sleeve 一旦分配就独立运行到结束，
  不做定期恢复目标权重。定期再平衡会改变收益与回撤，是真实组合管理的一部分。
