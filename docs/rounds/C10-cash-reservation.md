# 迭代记录 C10：挂单资金冻结与误熔断

这一轮由压力测试触发，发现两个互相牵连的严重缺陷。

## 缺陷 1：挂单不冻结资金（严重）

用 200 万账户并发下 300 笔限价买单，全部成功挂单，但：

```
open_orders: 300
cash: 2,000,000.00     ← 一分钱都没被占用
```

再单笔验证：100 万账户挂一张 68.3 万元的买单，现金仍是 100 万。

**后果**：同一笔钱可以支撑无限多挂单。若这些单同时成交，账户会被扣成负数，
账本与持仓全部失真。真实券商不会允许这种状态。

### 修复

新增两个概念：

- `reserved_cash(account_id)`：所有**未完成买单**的（剩余数量 × 限价 + 预估手续费）之和；
- `available_cash(account_id)` = 账面现金 − `reserved_cash`。

应用位置：

| 位置 | 使用 |
|---|---|
| 风控 `RiskContext.cash` | 可用现金（挂单占用后） |
| 成交时余额检查 | 可用现金，但**排除本单自身**的预留 |
| `PortfolioService.overview` | 新增 `available_cash` 与 `reserved_cash` 字段 |

卖出方向同理：`reserved_quantity()` 汇总未完成卖单，持仓展示的
`available_quantity` 为「可卖 − 卖单冻结」，避免同一批股票被挂两次。

## 缺陷 2：挂单被误判为亏损，直接触发熔断（严重）

加上冻结后立刻出现新问题：

```
second order -> 409 trading halted: daily loss limit hit (-68.32% <= -5.00%)
```

一笔正常挂单让账户自我熔断。

**根因**：`_equity()` 收到的是刚改成"可用现金"的值，
于是权益 = 可用现金 + 持仓市值 = 账面现金 − 冻结 + 持仓。
68.3 万冻结被当成 68.3 万亏损。

**修复**：权益必须用**账面现金**计算，与冻结无关。
冻结只影响"还能下多少单"，不影响"账户值多少"。

修复后同一场景：

```
order1 200  notional 683,000.00
order2 -> 409 insufficient cash: need 683,177.58, available 316,822.42
breaker False
```

既挡住超支，又不误熔断。

## 新增测试（4 项）

| 测试 | 断言 |
|---|---|
| `test_resting_buy_reserves_cash` | 预留额 = 数量 × 限价 × (1+费率)；超额下单被拒 |
| `test_cancelled_order_releases_cash` | 撤单后可用资金完全恢复 |
| `test_filled_resting_order_consumes_reservation` | 成交后预留清零，现金按实际成交价扣减 |
| `test_resting_orders_do_not_trip_breaker` | 60% 权益的挂单不触发日损失熔断，且仍能继续下单 |
| `test_resting_sell_locks_shares` | 卖单冻结股份，重复卖出同一批被拒 |

其中 `test_filled_resting_order_consumes_reservation` 还验证了一个有趣的会计事实：
限价 95 的买单以 94 成交时，释放的预留（95×20）大于实际支出（94×20），
可用资金会**上升**——这是价格改善，不是 bug。

## 教训

压力测试的价值不在延迟数字，而在**并发下暴露的状态缺口**。
单线程跑一笔挂单看不出问题；300 笔一起来，"没有冻结"立刻变成超支风险。
而修完冻结又暴露了第二个 bug（权益口径），说明资金相关的三个概念必须严格区分：

1. **账面现金**：账户真实有多少钱（权益用）；
2. **可用现金**：还能下多少单（风控与下单用）；
3. **冻结**：已承诺但未成交（只在上面两者之间转换）。

任何一处混用，都会同时产生"资金失控"和"风控误判"两类问题。
