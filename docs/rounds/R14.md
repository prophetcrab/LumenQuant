# R14 性能优化

## 需求设计
在不改变行为的前提下降低首屏体积、数据库读放大与并发尾延迟。验收：
- 前端首屏不再包含全部页面代码；
- 500 根 K 线在 20 并发下 0 错误、P95 < 500ms；
- 组合分析在 15 并发下 P95 < 200ms。

## 代码编写
1. **连接池**：SQLite 默认 5+10，爆发读请求排队到秒级 → 改为 20+30，`pool_timeout=10s`。
2. **TTL 缓存 + 单飞**：`core/cache.py`；行情快照 1.5s、K 线 2s；`get_or_load` 用每 key 锁合并同刻并发加载。
3. **复合索引**：`market_candles(symbol,timeframe,open_time)`、`equity_snapshots(account_id,created_at)`。
4. **前端路由分割**：`React.lazy` + `Suspense`，页面级 chunk。
5. **ECharts 按需注册**：只引入 line/bar/candlestick/pie/scatter + grid/tooltip/dataZoom/markLine + canvas。

## 压测数据（2560×1440 开发机，本机环回）

| 场景 | 优化前 | 优化后 |
|---|---|---|
| K 线 500 根 × 300 请求 / 20 并发 | 120 错误，P50 3008ms，P95 15017ms | 0 错误，P50 164ms，P95 226ms |
| 行情快照 300 / 20 并发 | 0 错误，P50 44ms | 0 错误，P50 44ms（缓存命中） |
| 组合分析 200 / 15 并发 | — | 0 错误，P50 50ms，P95 83ms |
| 前端 ECharts chunk | 1169 KB（gzip 392 KB） | 654 KB（gzip 223 KB） |
| 前端首屏 | 单包 1487 KB | shell + 总览，其余页面按需 |

## 代码审查
1. 缓存返回的是同一 list 对象，调用方若原地修改会污染缓存 → 当前所有读取路径都只序列化，不修改；README 中标注约束。
2. 单飞锁按 key 常驻，理论上可无限增长 → key 空间受“标的×周期×limit”限制，实际有界。
3. 缓存 TTL 短于行情 tick，用户不会看到过期价格超过 2 秒。
4. 索引变更对既有 SQLite 文件不会自动创建 → 删库重建或 R20 提供初始化脚本，已记录。
