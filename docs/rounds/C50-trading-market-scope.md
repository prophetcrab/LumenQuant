# 迭代记录 C50：交易页的跨市场标的列表

## 动机

C49 的冒烟检查覆盖了 13 个页面的加载状态，但没有检查**切换账户之后**
页面是否还一致。切换账户是改变整个页面语义的动作——市场、货币、规则、可用标的全变。
这一轮专门验证切换后的状态。

## 缺陷：加密账户看到 14 个标的，包含 8 只 A 股

交易页的标的列表是这样取的：

```ts
const snapshots = useSnapshots();     // 没有传市场
```

`useSnapshots()` 不带参数时调用 `GET /api/market/snapshots`（不传 `market`），
后端返回**全部**标的。实测：

```
account: 最终验收加密 · 模拟 · 加密
symbolCount: 14
first: ["000001.SZ", "000858.SZ", "002594.SZ", ...]
```

加密账户的下拉里出现了平安银行、五粮液、招商银行……

选中它们的后果是提交时被后端拒绝：

```
POST /api/trading/orders
422 {symbol} 属于 cn_stock 市场，与账户市场 crypto 不一致
```

用户会看到一条明确但多余的报错——这个选项本来就不该出现在这里。

### 修法

```ts
const market = account?.market;
const snapshots = useSnapshots(market);
```

后端按 `market` 过滤，前端拿到 6 个加密标的。

### 附带问题：切换后选中的标的不存在

标的列表变了，但 `symbol` 状态还停在旧市场的值。`<select value="BTCUSDT">`
的选项里没有 `BTCUSDT` 时，浏览器会显示第一项而 state 仍是旧值——
用户看到的和提交的不是同一个标的。

加了一个 effect：列表变化后，如果当前标的不在其中，回落到该市场的基准标的
（A 股 600036.SH / 加密 BTCUSDT），而不是字母序第一项。

为什么不用字母序第一项：切到加密账户会得到 `ADAUSDT`。
技术上可交易，但对一个刚切换过来的用户来说，"为什么默认是 ADA" 是个不必要的疑问。
基准标的（BTCUSDT）符合直觉。这与 C46 修 AI 助手时是同一个判断。

## 设计取舍

- **为什么在前端传 market 而不是在服务端按账户过滤**：`/api/market/snapshots`
  是公开的行情接口，不绑定账户——它也应该能列出全部标的（行情页就需要）。
  按账户约束是交易页的职责，放在调用方更合适。
- **为什么 effect 依赖 `market`**：只依赖 `snapshots.data` 时，
  同一次切换可能拿到缓存中的旧 market 数据，effect 不会重跑。
- **为什么同时清空 `limitPrice`**：限价输入框会保留上一个标的的价格，
  切换标的后这个数字对应的是完全不同的资产，必须清掉让它重新取当前价。
