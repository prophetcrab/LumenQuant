# 迭代记录 C32：真实数据全链路验收，AI 助手接入风控

## 动机

此前所有验收都在**合成数据**上完成。合成数据能验证逻辑，但验证不了
"真实行情接进来之后系统还对不对"。这一轮用腾讯行情端点跑真实 A 股数据，
并在过程中抓到了两个只有真实环境才会暴露的缺陷。

## 缺陷一：只有真实数据时，A 股标的一只都没有

`seed_market=False` + `cn_data_source=tencent` 是"纯真实数据部署"的合理配置
（不要合成加密行情，只要真实 A 股）。此时启动日志正常，但同步全部失败：

```
sync: {"ok": false, "symbols": [{"code": "600519.SH", "error": "本地未登记标的 600519.SH"}]}
```

根因在 `main.py`：`CnMarketEngine` 的构造挂在 `seed_market` 下面——

```python
if settings.seed_market and settings.cn_symbols_enabled:
    cn_market_engine = CnMarketEngine(db, settings)
```

`CnMarketEngine` 同时承担两件事：登记标的目录、生成合成 K 线。
只有前者与合成数据有关，后者才该受 `seed_market` 控制。
关闭合成行情时把目录一起关掉了，于是同步器拿不到标的元数据（交易所、板块、手数、涨跌停），
连报价都发不出去。

**修法**：拆开两个职责。`cn_symbols_enabled` 只决定是否登记目录，
`seed_market` 才决定是否启动合成引擎：

```python
if settings.cn_symbols_enabled:
    if settings.seed_market:
        cn_market_engine = CnMarketEngine(db, settings)
    else:
        CnMarketEngine(db, settings).ensure_symbols()   # 只登记，不生成行情
```

## 缺陷二：空仓跑赢下跌行情，却被说成"更高暴露"

真实数据下 600519 有 401 根日线，但一手 100 股约 13.2 万，
10 万初始资金买不起，回测 0 笔交易、收益 0%。同期基准跌 11.58%，
于是"超额 +11.58%"。系统给出：

> 收益高于基准但alpha为负：超额主要来自更高暴露，不是选股或择时能力

**策略全程空仓，beta = 0，"更高暴露"完全说反了。**
这个结论会直接误导用户——他可能以为自己找到了一个能规避下跌的策略。

**修法**：在 `_verdict` 的跑赢分支里先判断暴露：

```python
if abs(beta) < 0.2:
    return "几乎全程空仓：超额来自回避下跌，不是选股或择时能力；请先确认策略是否真的产生过交易"
```

beta ≥ 0.2 时保持原有措辞（真正的"高暴露但无 alpha"）。

## AI 助手补齐风控能力

助手能查账户、持仓、订单、行情、策略、回测、自动实例，唯独答不了
"我现在能开仓吗""哪些实例没设止损"——而这两个恰恰是实盘前最该问的。

把风控聚合逻辑从 `risk/router.py` 提取到 `risk/overview.py`，
路由与 AI 工具共用同一份定义，避免两边各算一套、数字对不上。

新增只读工具 `risk_overview`：
- 熔断状态与原因、日内基准、峰值
- 限额（单笔/单标的/频率/日损失/回撤）
- 敞口（权益、可用现金、冻结、持仓市值、敞口比）
- 逐仓浮盈
- 实例止损保护情况
- 未受保护实例的告警列表

本地意图里把风控放在**最前面**匹配——"止损""开仓"这类词同时命中
"持仓""账户"的模式，放在后面会被抢先。
