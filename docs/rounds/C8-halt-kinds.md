# 迭代记录 C8：区分日内熔断与回撤熔断

## 问题

C7 实现了跨日重置，但两类熔断共用一个 `breaker_reason` 字段，导致跨日时
**回撤熔断也被一并解除**。

这很危险：25% 回撤是组合级结构风险信号，不该因为"到了第二天"就恢复正常交易。
按原实现，一个连续亏损的账户会每天开盘自动解锁、继续下单、继续亏损。

## 实现

`RiskState` 拆为两个原因字段（幂等迁移自动加列）：

| 字段 | 含义 | 跨日 |
|---|---|---|
| `daily_reason` | 日损失触线 | **清空**（新的一天有新额度） |
| `drawdown_reason` | 峰值回撤触线 | **保留**，只能人工 `reset` |
| `breaker_reason` | 兼容字段，保留最近一次原始原因 | 无回撤时清空 |

`trip()` 按原因文本归类（含 `drawdown` 判定为回撤），`state()` 返回：

- `breaker_active`：任一原因为真；
- `halt_kind`：`"drawdown"` 优先于 `"daily"`；
- `breaker_reason`：展示具体原因。

前端徽章区分显示"日内熔断"与"回撤熔断（需人工重置）"。

## 验证

| 测试 | 断言 |
|---|---|
| `test_drawdown_halt_survives_daily_rollover` | 跨日后仍熔断、类型为 drawdown，只有 reset 才解除 |
| `test_daily_halt_releases_while_drawdown_persists` | 两类同时触发时，跨日只释放日内额度，回撤仍生效 |
| `test_daily_baseline_rolls_over_on_new_day` | 纯日内熔断跨日自动释放（回归） |
| 全量 | **205 passed** |

## 语义说明（写进文档，避免误解）

- 日内熔断：保护"今天不要再亏更多"，跨日自动恢复 —— 符合券商日内风控惯例。
- 回撤熔断：保护"这个策略/账户已经失效"，必须人工复核后重置 ——
  自动恢复等于把风险控制变成摆设。

两者的恢复策略不同，所以不能共用状态。

## 仍未做

- 回撤熔断解除后没有"冷静期"或"缩量恢复"机制（例如恢复后首日仓位减半）；
- 没有按策略实例级别的熔断（当前是账户级）。

这两项属于增强而非缺陷，已记入待办。
