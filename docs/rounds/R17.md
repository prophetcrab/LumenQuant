# R17 2K 视觉打磨与实盘下单链路

## 需求设计
两件事：把「2K 27 寸浅色工作台」从能用做到好看好用；补齐 R11 遗留的缺口——实盘账户此前仍走模拟撮合。

## 2K 视觉验收（11 页全量截图，2560×1440）
`docs/reviews/R17/*.png`：总览、行情、交易、自动运行、策略库、回测、组合、账户、AI 助手、数据、系统。

发现并修复的视觉/口径缺陷：
1. **环形图动画残弧**：轮询刷新重启 400ms 动画，截图与肉眼都能看到半圈 → 关闭动画（`charts.ts`）。
2. **回撤轴刻度重复**：小于 0.1% 的回撤全部显示 "-0.0%" → 固定两位小数并给纵轴留白。
3. **权益曲线贴顶被裁**：数据最大值等于轴最大值时曲线贴边不可见 → `niceBounds()` 向外取整到可读步长。
4. **策略页比例失衡**：通用 `analysis-grid` 把列表拉到 2/3 宽 → 新增 `list-detail-grid`（400px + 1fr）。
5. **K 线区高度不足**：2K 下图表偏扁 → 高度 528 → 656。
6. **响应式**：三套栅格在 <1500px 时统一单列。

## 数据口径缺陷（被视觉验收暴露）
- 组合页“样本收益率 +9.95%”与顶部“累计收益 -0.04%”矛盾：入金被算成收益。
- 修复：快照新增 `net_contributions`；收益改为**时间加权**（(eq_t − eq_{t−1}) / 资本在险），累计收益按净投入计算；新增回归测试 `test_deposit_is_not_counted_as_return`。
- 迁移：`Database._apply_light_migrations()` 对既有库做幂等加列（`ALTER TABLE ... ADD COLUMN`）。

## 实盘下单链路（补 R11）
- `TradingService._place_live_order()`：实盘账户下单选 `BrokerPort`，用**交易所真实成交**回写订单、持仓、账本与成交记录。
- 实盘账户缺密钥 → 403，并提示所需环境变量。
- `POST /api/trading/orders` 对实盘账户额外要求 `X-Live-Confirm: true`（双开关）。
- 测试 3 例：无 broker 拒绝、真实成交镜像到持仓/账本、限价挂起不建仓。
