# 迭代记录 C24：参数优化（网格搜索）

## 动机

平台已能回测单个参数组合，但研究真实问题需要"这组参数是不是碰巧好"。
网格搜索是基础能力，同时**最容易误导人**——所以本轮的重点不是"能搜"，
而是"搜完能判断结果是否可信"。

## 性能基线（先测再设计）

用真实 A 股数据（招商银行 800 根日线）跑 30 组 sma_cross 参数：

```
30 组回测耗时 149ms，平均 5.0ms/组
```

结论：同步执行即可，不需要任务队列。500 组上限下最坏约 2.5 秒。

## 实现

`app/modules/backtest/optimiser.py`：

### 1. 参数空间与护栏

- 最多 500 组组合、单参数最多 50 个候选值；
- 至少 250 根 K 线（且需覆盖策略暖机 + 60 根样本外）；
- 非法组合（如 `fast >= slow`）计入 `rejected` 而非中断整个搜索。

### 2. 样本内 / 样本外

按 70/30 切分：全量选优，再分别在两段上回测，输出：

```
in_sample_return_pct  /  out_of_sample_return_pct
```

这样"样本内 +57% 但样本外 -9%"会被直接看见。

### 3. 四种优化目标

| objective | 计算 |
|---|---|
| `return` | 总收益 |
| `sharpe` | Sharpe |
| `calmar` | 收益 / 最大回撤 |
| `risk_adjusted`（默认） | 收益/回撤 + 0.5×Sharpe |

单看收益会奖励"高杠杆式"策略，所以默认用风险调整。

### 4. 过拟合告警（核心）

自动检测并警告：

- 组合数 ≥ 100 → "最优结果很可能是过拟合"；
- 盈利组合占比 < 20% → "策略在该标的上缺乏普遍有效性"；
- 最优参数交易数 < 5 → "统计上不足以判断"；
- 样本内为正、样本外为负 → "典型的过拟合信号"；
- 样本外区间不足 60 根 → "无法验证稳健性"；
- **数据源为合成行情** → "走势过于规整，任何策略都能得到漂亮数字"。

最后一条是本轮实测触发的：在 BTCUSDT 合成数据上跑出
**+126%、100% 组合盈利、Sharpe 11.35**——这组数字本身就在尖叫"假的"。

### 5. 邻域稳健候选

除最优解外，额外返回"得分接近最优、交易数 ≥ 5、收益为正"的组合。
只在某一个精确取值上有效的参数通常是噪声。

## API

```
POST /api/backtests/optimise
{
  "strategy": "sma_cross",
  "symbol": "600036.SH",
  "timeframe": "1d",
  "bars": 800,
  "space": {"fast": [5,10,15,20], "slow": [20,30,40,60], "require_regime": [true,false]},
  "objective": "risk_adjusted"
}
```

优化结果**不写入回测历史**（避免几十条无意义记录污染列表），有专门测试锁定。

## 前端

回测页新增「单次回测 / 参数优化」两个标签页：

- 策略、标的、周期选择器提升为共享（原来只在单次回测页内）；
- 参数候选值按默认值自动预填一组（0.5×–2× 默认值），开箱即可运行；
- 实时显示组合数，超过 500 禁用搜索；
- 结果区：4 个统计卡 + 参数排名表（含样本内外列）+ 邻域稳健候选表 + 告警横幅。

## 真实数据验证

```
策略 sma_cross · 招商银行 · 800 根日线 · 32 组参数
最优: fast=15 slow=60 require_regime=off
  样本内 +24.94%   样本外 +7.02%
  盈利组合 25/30 (83.3%)
  收益区间 -10.67% ~ +29.74%
  耗时 394ms
告警: 无（样本充足、盈利面广、样本外为正）
```

样本外仍为正、且盈利组合占 83%，说明这组参数不是孤立的噪声点——
但也从 +24.94% 衰减到 +7.02%，说明其中相当部分是行情本身。

## 测试（17 项新增）

| 类别 | 覆盖 |
|---|---|
| 网格构建 | 笛卡尔积、空空间、超限、非法组合跳过 |
| 排名 | 按得分降序、top N |
| 样本划分 | 内外样本长度之和等于总数、两段都有收益 |
| 告警 | 宽网格、少交易、样本外不足、合成数据 |
| 参数解析 | 形状校验（非数组/非对象） |
| API | 正常返回、四类错误、不污染历史 |

全量：**264 passed**。

## 教训

**优化器最大的风险不是搜得慢，而是让人相信搜出来的数字。**
一个只输出"最优参数 + 收益"的网格搜索，几乎必然诱导用户过拟合。

所以本轮把一半工作量放在"如何否定自己的结果"上：
样本外、盈利面、交易数、邻域稳健性、数据源真实性——
任何一项不合格，都应该让用户先怀疑结论，而不是直接拿去实盘。
