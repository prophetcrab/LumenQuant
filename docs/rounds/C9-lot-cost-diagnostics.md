# 迭代记录 C9：A 股自动交易的仓位上限诊断

## 背景

双市场端到端跑通后，创建了一个 A 股自动交易实例：

```
strategy=macd_momentum, symbol=600519.SH（约 2570 元/股）
position_pct=0.15, max_order_notional=200,000
账户资金 800,000
```

日志里只有 `created`，之后没有任何信号记录。

## 分析

算一下就知道问题：

- 一手 = 100 股 × 2570 = **257,000 元**
- 仓位预算 = 800,000 × 15% = 120,000 → 已小于一手
- 即便预算够，`max_order_notional = 200,000` 仍小于一手

两者共同导致 `quantity = floor(budget / lot) * lot = 0`。

## 问题不在"不能下单"，而在"说的原因不对"

原代码统一记录：

```
可用资金不足最小下单量，跳过买入
```

但该账户有 80 万现金，**并不缺钱**。真正的原因是单笔名义上限太低。
用户会去查余额、去入金，而正确操作是调高 `max_order_notional`。

## 修复

### 1. 后端区分三种原因

| 情形 | 日志 |
|---|---|
| 一手成本 > 资金 且 > 名义上限 | "一手 100 股约需 257,000.00，超过可用资金 120,000.00 且超过单笔上限 200,000.00" |
| 一手成本 > 名义上限（资金充足） | "一手 100 股约需 257,000.00，超过单笔上限 200,000.00；请调高 max_order_notional" |
| 资金不足 | "可用资金 X 不足以买入一手（约需 Y）" |

三条消息都带具体数字，可以直接算出该调哪个参数。

### 2. 前端创建实例时预检

在"新建自动运行实例"弹窗里，选定 A 股标的与名义上限后实时计算一手成本：

- 上限低于一手成本时，输入框下方显示错误：
  "低于一手成本 257000.00 元，实例将无法建仓"；
- 该状态下"创建并启动"按钮禁用。

把错误挡在创建前，而不是让用户第二天看日志才发现。

## 验证

| 检查项 | 结果 |
|---|---|
| 新增用例 `test_sizing_explains_notional_cap_not_cash` | 80 万资金 + 5 万上限 → 日志指明"单笔上限"而非"资金不足"，且未建仓 |
| 全量测试 | **206 passed** |
| 前端类型检查 | 0 错误 |
| 前端构建 | 成功 |

## 经验

A 股的一手成本是加密市场没有的概念：加密可以买 0.0001 BTC，
而 A 股最少一手可能就要几十万。所有涉及"按金额换算数量"的地方都要
把**一手成本**当作一等公民，否则会出现"资金充足却无法建仓"的怪现象。

涉及的位置已排查：
- 回测引擎（C2 已处理，输出 `insufficient_capital` 与警告）
- 运行时建仓（本轮处理）
- 前端实例创建（本轮处理）
- 手动下单（由手数校验直接拒绝，错误信息已含手数要求）
