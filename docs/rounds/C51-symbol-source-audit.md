## 缺陷：回测页默认标的固定为 BTCUSDT

回测与账户无关——研究可以看任意市场。所以列出全部 14 个标的是合理的。
但**默认值**不该固定：A 股账户打开回测页，看到 BTCUSDT 已选中，
不加思索地点"运行回测"，得到的是一份加密货币报告。

修法：默认标的跟随账户市场，优先该市场基准（A 股 600036.SH / 加密 BTCUSDT），
其余标的仍全部可选。

### 关键细节：不能覆盖交接来的标的

策略库可以把标的带进回测页（C29）。如果用户在策略库里明确选了 ETHUSDT，
而当前账户是 A 股，这条交接不该被"跟随市场"的默认值覆盖——
用户的选择是显式的，默认值只是兜底。

实现上加了一个 ref 标记：

```ts
const handoffSymbol = useRef(handoff.current?.symbol);
useEffect(() => {
  if (handoffSymbol.current) {
    // 交接的标的在列表里 → 保持它，之后不再干预
    if (rows.some((item) => item.code === handoffSymbol.current)) {
      handoffSymbol.current = undefined;
      return;
    }
    return;
  }
  // 否则才按市场选默认
  ...
});
```

保留 `undefined` 的两种含义：

- **列表还没加载**：等下次 effect 再判断，不清除标记
- **标的已在列表中**：交接完成，清除标记，后续用户手动切换交给用户

## 设计取舍

- **为什么回测页不像交易页那样只列出账户市场的标的**：回测是研究工具，
  用户可能想研究一个自己不交易的市场（比如用 A 股账户研究 BTC 策略）。
  交易页必须限制，因为下单会被服务端拒绝；回测没有这个约束。
- **为什么默认值要跟随市场**：默认值是会被大量使用的。研究工具的第一屏
  应该回答"我关心什么"，而不是"系统有什么"。
- **为什么用 ref 而不是 state**：交接是"消费一次"的语义，不需要触发重渲染。
  用 state 会让 effect 依赖自身变化，容易写成循环。
