# 迭代记录 C46：AI 助手的市场感知

## 动机

AI 助手是用户最早接触的功能，也是最容易"看起来对、实际错"的功能。
它回答的是具体数字（收益、信号、回撤），用户很难发现问题。

C32 给助手加了风控工具，但没检查另一件更基础的事：
**助手知道用户是哪个市场吗？**

## 缺陷：A 股账户问策略，回答比特币

用一个 A 股账户提问：

```
双均线信号   -> sma_cross 在 BTCUSDT 1h 最新收盘 K 线的结论是「观望」
回测MACD    -> macd_momentum 在 BTCUSDT 1h 上回测 12.24%，同期买入持有 77.56%
```

两个问题：

1. **跨市场**：账户是 A 股，分析的是加密货币，这个账户根本无法交易它
2. **时间周期错**：A 股 1h 数据本就稀薄，却默认用 1h

根因是一行硬编码：

```python
"symbol": symbol or "BTCUSDT",
```

当用户没说标的时，永远回落到比特币，与账户无关。

## 修法

### 1. 按账户市场选默认标的

```python
default_symbol = symbol or self._default_symbol(account_id)
```

`_default_symbol()` 先读账户所属市场，优先返回该市场的基准标的
（A 股 600036.SH / 加密 BTCUSDT），不存在则退到第一只有效标的。

为什么不用"第一只"：按字母序会得到 ADAUSDT——技术上可行，但对
"双均线信号"这种问题是个令人意外的答案。基准标的更符合预期。

### 2. 按市场选默认周期

A 股默认 1d，加密默认 1h。A 股的 15m/1h 数据依赖同步覆盖，
用日线更可能命中真实数据。

### 3. 识别 A 股代码

原来的 `SYMBOL_RE` 只匹配 `BTC|ETH|SOL|BNB|XRP|ADA`。
新增 `CN_SYMBOL_RE`：

```
"600036"     -> 600036.SH     （6/9 开头 = 沪市）
"000001"     -> 000001.SZ     （0/2/3 开头 = 深市）
"688981"     -> 688981.SH
"430047"     -> 430047.BJ     （4/8 开头 = 北交所）
"600036.SH"  -> 600036.SH     （显式后缀优先）
```

交易所推断是确定性的（A 股代码段有明确分配），不需要查表。

修完后：

```
A股 双均线信号   -> sma_cross 在 600036.SH 1d ...
加密 双均线信号   -> sma_cross 在 BTCUSDT 1h ...
600036 双均线信号 -> sma_cross 在 600036.SH 1d ...
000001 双均线信号 -> sma_cross 在 000001.SZ 1d ...
```

## 设计取舍

- **为什么不要求用户必须指定标的**：对话式界面里"双均线信号"是最自然的问法。
  要求每次都带代码会大幅降低可用性。合理的默认值比强制输入更好。
- **为什么默认标的优先基准而非"第一个"**：默认值会被大量使用，
  它的合理性直接决定第一印象。BTCUSDT/600036.SH 是各自市场最常被讨论的标的。
- **为什么交易所推断不查数据库**：`600036.SH` 和 `600036` 应该在**解析阶段**
  就得到同一个结果，不依赖该标的是否已登记。查库会让"未同步的代码"变成另一个标的。

## 后续

- 助手仍无法理解"茅台""招行"这类中文简称。可以做一张别名表，
  但需要业务维护，优先级低于当前的功能缺口。
- `_default_symbol` 依赖 `toolbox.market.list_symbols`，每次调用都查库。
  对话频率低，暂不需要缓存。
