# 迭代记录 C5：请求契约收紧

## 动机

C4 发现的 `market` 字段丢失不是孤例，而是一个**模式**：
Pydantic 默认忽略未声明的字段，导致"客户端传了、服务端没接、接口还返回 200"。

这类问题不会抛异常、不会写日志、不会让测试变红——只有对照返回值才能发现。

## 改动

给全部 7 个请求体模型加上：

```python
model_config = ConfigDict(extra="forbid")
```

覆盖：账户创建、标的创建、回测请求、下单请求、策略信号请求、
策略实例创建、助手对话。

现在客户端多传字段会立即得到 `422`，并指出是哪个字段不被接受。

## 兼容性检查

全部 199 项测试（含 45 项 A 股/网关用例、12 项前端调用的接口契约）通过，
前端所有调用都未受影响——说明既有调用本来就没有多传字段，收紧没有破坏兼容性。

## 新增测试

`tests/integration/test_request_contracts.py`：

1. 五类接口各传一个多余字段 → 全部 422；
2. 合法请求仍正常创建账户与标的（防止"一刀切把正常请求也拒了"）。

## 后续

同类收紧应继续做在：
- 策略参数（已用 `extra="forbid"`，无需改动）；
- 环境变量（pydantic-settings 已是 `extra="ignore"`，这是**有意为之**：
  部署时多配一个变量不应导致服务起不来，但应记录到启动日志）。
