# 迭代记录 C30：策略库直连自动运行，实例可编辑

## 动机

C29 打通了"策略库 → 回测"，但另一条更常走的路径还断着：调好参数后要让它**真的跑起来**，
得切到自动运行页，把策略、标的、周期、参数再填一遍。同时盘点时发现两个实际缺陷：

1. `PATCH /api/runtime/instances/{id}` 后端早就实现了（参数、仓位、上限、三种止损），
   前端从未调用——**实例创建之后任何配置都改不了**，只能删了重建，
   而重建会丢掉执行次数和日志。
2. 新建实例的标的下拉框列出全部标的，不区分账户市场。A 股账户默认选中 `BTCUSDT`，
   用户填完整个表单点创建，才被后端以 422 拒绝。

## 实现

### 1. 一键建实例

策略库新增"建成自动实例"按钮，把策略、标的、周期、参数序列化进 URL，
跳转 `/runtime?...`。自动运行页在首次渲染前读入，直接打开创建对话框并预填：

- 策略/标的/周期作为 state 初值
- 参数用 `{ ...schema 默认值, ...传入值 }` 合并（与 C29 同一套幂等逻辑，
  避免 StrictMode 双重执行覆盖）
- 消费后清空 query

### 2. 实例编辑

表格每行加"编辑"，打开对话框可改：单次仓位、单笔名义上限、止损/止盈/移动止损、策略参数。
**策略、标的、周期显示为只读**——改了就不再是同一个实例，历史日志会失去意义。

保存走已有的 `PATCH` 接口。止损在下一个调度 tick（≤6 秒）生效，
策略参数在下一根已收盘 K 线生效，对话框里写明了这个区别。

### 3. 标的按账户市场过滤

策略库与自动运行页的标的下拉都只显示当前账户市场可交易的标的：
A 股账户只看到 8 只 A 股，加密账户只看到 6 只加密货币。切换账户时自动回落到该市场第一只。

### 4. 手动评估补上止损扫描

`POST /api/runtime/tick` 之前只跑信号评估，不跑 `protect_positions()`。
也就是说：调度器会触发的止损，点"立即评估"不会触发。
用户恰恰是在手动验证时最需要它，这个不一致会直接误导判断。
现在 tick 与调度器顺序完全一致——先保护性离场，再评估信号。

## 设计取舍

- **为什么不自动给实例配默认止损**：止损会改变策略行为，默认开启等于替用户做了交易决策。
  风险中心页（C28）会把"运行中但无保护"的实例点名列出，让缺省状态可见而不是悄悄兜底。
- **为什么编辑不允许改标的**：改标的等于换了一个策略实例。允许改会写出一段跨标的的日志，
  回看时分不清哪次执行对应哪只股票。停止后新建的代价很小。
- **为什么标的过滤放在前端**：后端本来就校验市场一致性（返回明确的 422 文案），
  前端过滤只是避免用户走进一个必然失败的路径；后端校验保留，防止绕过 UI 的调用。

## 后续

- 实例级止损目前是"整仓单一规则"，组合层面的相关性/总敞口约束还没有。
- 新建实例仍要求用户手动确认单笔上限，A 股高价股（如 600519 一手约 15 万）
  容易被默认的 2 万上限挡住——对话框已有明确提示，但可以进一步按标的一手成本预填。
