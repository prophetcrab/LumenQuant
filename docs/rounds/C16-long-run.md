# 迭代记录 C16：加速长时间运行

C15 诚实列出了四项未验证内容，本轮处理其中一项：**长时间运行**。

## 方法

用 `CnSessionClock(speed=20000)` 把模拟时钟加速约 20,000 倍：
1 秒真实时间 ≈ 5.5 小时模拟时间。跑 60 次 tick（约 3.6 秒真实时间），
覆盖约 25 小时模拟时间，跨过午休、收盘与次日开盘。

## 第一次检查的结果（虚警）

脚本报告"12 根 K 线落在交易时段外"。查明细后确认这些是**日线**
（时间戳为当日北京时间 00:00），是正确设计，不是缺陷。

教训：跨周期校验必须按 timeframe 分别断言，否则会把日线的合法时间戳
当成异常。

## 修正后的检查（真实结论）

| 指标 | 结果 |
|---|---|
| 60 次 tick 实际耗时 | 3.61 秒 |
| 新增 K 线 | 408 根（含日线） |
| 模拟时钟推进 | 25.18 小时 |
| 内存当前 / 峰值 | 498.8 KB / 547.4 KB |
| 15 分钟线越界数量 | **0** |
| 日线时间戳 | 全部为 00:00（北京时间） |
| 日线重复 | 无（每日一根） |

内存峰值仅五百余 KB，`_live` 与 `_locked` 字典大小受标的数量约束（≤ 8），
没有随 tick 次数增长。

## 固化为测试（2 项）

`tests/integration/test_long_run.py`：

1. `test_accelerated_run_keeps_data_inside_sessions`
   - 时钟必须推进超过 6 小时；
   - 所有 15m K 线必须在 09:30–11:30 / 13:00–15:00 内；
   - 日线时间戳必须为本地 00:00 且不重复。
2. `test_engine_does_not_accumulate_live_state`
   - `_live` 与 `_locked` 大小不超过标的数量，防止内存泄漏。

## 仍未验证

- **真实 24 小时+ 连续运行**：加速测试无法覆盖真实的定时器漂移、
  数据库文件增长、日志轮转等问题；
- **跨月与跨年**：需要真实日历推进，加速测试只能覆盖数日；
- **真实行情与真实券商网关**：需外部条件。

这三项已写入 `docs/delivery/acceptance.md` 的"未验证项"，不做虚假声明。
