# 迭代记录 C6：风控基准与组合一致性

## 验证方法

在一个进程内直接构造 A 股账户、下两笔买单，然后核对：

- 权益恒等式（现金 + 持仓市值 = 权益）
- 组合分析可用性
- 风控状态

## 发现的问题

### 风控日内基准为 0，熔断器形同虚设

```
risk breaker False  day_start 0.0
```

`risk_states.day_start_equity` 只在 `PortfolioEngine` 每 15 秒的快照循环里写入。
如果用户刚建账户就下单，或后台引擎尚未跑过一轮，`day_start_equity` 仍是 0。

而日损失公式是：

```python
if limits.max_daily_loss_pct and ctx.day_start_equity > 0:
```

基准为 0 → 条件不成立 → **熔断器完全跳过，且不报任何错误**。
用户以为有 5% 日损失保护，实际上第一段交易时间完全没有。

修复：新增 `RiskService.ensure_baseline()`，在下单路径首次发现基准为 0 时，
用当前权益初始化日内基准与峰值。它只在调用方事务内 `flush`，不自行提交，
避免破坏下单的原子性。

## 验证

| 检查项 | 结果 |
|---|---|
| 权益恒等式 | delta = 0.0 |
| 两笔买入费用 | 5.20 / 18.76 元（按各自名义金额，最低佣金生效） |
| 组合敞口 | 9.17% |
| 归因 | 两个标的分别计入各自手续费损耗 |
| 风控基准 | 首次下单后自动初始化为当前权益 |
| 熔断可达性 | 基准初始化后，-10% 权益会触发 5% 日损失熔断（用例验证） |
| 全量测试 | **200 passed** |

## 同类风险排查

以下路径都会读取 `day_start_equity`，已确认修复后都受益：
- `TradingService.place_order`（下单前置检查）
- `PortfolioEngine.tick`（后台快照 + 熔断评估）
- `/api/risk/observe`（手动喂权益）

还有一处**已知限制**：日内基准不会在跨日时自动归零。
当前实现里，`reset` 才能重建基准，后台引擎也不会在开盘时重置。
真实券商的做法是每个交易日开盘前重置日内亏损额度。
这一点已记入待办，属于"设计未完成"而非"bug 隐藏"。
