# R01 工程基座与账户模块

## 需求设计
建立可演进的后端骨架：类型化配置、数据库隔离、领域事件、审计日志、账户与资金账本；API 错误契约统一；为后续模块留出注入点。验收：账户可创建/查询/改名/归档、出入金有流水、重名与非法参数被拒绝、健康检查可用。

## 代码编写
- `core/`：Settings、Database（WAL/外键/忙等待）、EventBus、AppError、金额工具、审计。
- `accounts/`：Account、LedgerEntry、AccountService、REST 路由。
- `main.py`：应用工厂，便于测试注入临时 DB；`/health` 与 `/api/meta`。
- 测试：5 个单元用例 + 3 个 API 集成用例。

## 代码审查
发现并记录：
1. 重名账户在 `flush()` 阶段抛 IntegrityError，未被转换为业务错误 → 已修复（预检查 + 事务内捕获）。
2. 服务层自行 commit 与依赖层 commit 重复 → 当前幂等，保留但记入技术债，R14 统一事务边界。
3. 账户视图只含现金，不含持仓市值 → 后续由 portfolio 模块补齐，避免 accounts 依赖 trading。

## 优化
- SQLite 开启 WAL 与 `busy_timeout=5000`，降低并发读写锁冲突。
- 账本记录 `balance_after`，前端无需回放流水即可展示余额轨迹。
- 金额统一 8 位小数舍入，避免浮点尾差扩散。

## 模块测试
`pytest -q`：9 passed。覆盖初始入金、重名、出入金、余额不足、实盘开关、参数校验、归档限制、HTTP 错误契约、健康检查。

## 系统测试
TestClient 完整走通「创建 → 查询 → 入金 → 出金 → 流水 → 归档」，错误响应符合 `{error:{code,message}}`。
