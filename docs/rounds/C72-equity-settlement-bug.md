# 迭代记录 C72：在途资金没算进权益

## 怎么发现的

C71 之后用真实 A 股数据验证篮子回测，看到一组不可能的数字：

```
各 sleeve 收益：-0.04% / +1.95% / +2.73%
组合收益：      +316.33%
```

三个都在零附近，组合却是三倍。检查再平衡开关：`rebalance_bars=0` 时正常
（-7.64%），`rebalance_bars=20` 时变成 **+387.85%**。

先怀疑再平衡的数学。用两条构造曲线（一条持平、一条每根 -1%）单独测
`_combine`，结果正确。所以问题在输入——直接看 sleeve 的权益曲线：

```
600036.SH  first 300000  last 296408  min 14766   max 309927
   max bar return: +1785.45%   min: -94.71%
```

单根 K 线涨 17 倍再跌回去。这是数据层面的不可能。

## 根因

C57 引入 A 股卖出资金的 T+1 在途（`settling`）。卖出时：

```python
settled = round_money(cash - proceeds_before)
cash = proceeds_before          # 钱从 cash 移走
settling.append((release_day, settled))
```

而权益计算是：

```python
equity = cash + position.quantity * candle.close
```

**在途资金既不在 `cash` 里，也不在持仓里，于是凭空消失。**

- 卖出当根：权益跌掉全部卖出额 → -94.7%
- 释放当日：钱回到 `cash`，但它从来就没离开过总资产 → 看起来 +1785%

整个 A 股回测的收益、回撤、Sharpe、波动率，以及组合分析的相关性，
在这之后全部建立在一条错误的曲线上。

## 为什么之前没发现

C57 加这个改动时，测试只断言了"卖出当日不能再买入"和"收益数字变化合理"。
我用的是构造的价格序列（每天涨 0.4% / 跌 0.3%），一次 100% 仓位买卖后
权益本该接近初始资金，而 bug 造成的跳变恰好发生在序列中间——
`total_return_pct` 只看首末，中间怎么跳变都看不出来。

只有真实数据（多标的、多次进出、再平衡放大误差）才把这个缺陷顶出来。

## 修法

权益必须包含在途资金：

```python
settling_total = sum(amount for _day, amount in settling)
equity = cash + settling_total + (position.quantity * candle.close if position else 0.0)
```

末尾平仓的两条分支也一并修正。

修后真实数据：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 单根最大收益 | +1785.45% | +2.4% |
| 单根最大亏损 | -94.71% | -2.6% |
| 再平衡组合收益 | +387.85% | -7.74% |
| 不再平衡组合收益 | -7.64% | -7.64% |

再平衡与不再平衡的差异回到合理范围（-7.74% vs -7.64%）。

## 回归测试

两项，并且**验证过它们确实能抓住这个 bug**——临时回退修复后
`test_equity_includes_cash_held_for_t1_settlement` 立即失败，恢复后通过：

```python
# 10-11 的价格序列、90% 仓位，单根不可能超过 ±5%
assert max(returns) < 5
assert min(returns) > -5
```

第二项断言末尾权益与初始资金的偏离在 15% 以内。

## 教训

**只看首末值的指标掩盖中间过程的错误。** `total_return_pct` 是首末之比，
一条在中间塌陷又复原的曲线在它看来完全正常。以后给回测加"过程正确性"检查时，
应当验证逐根收益率落在合理区间，而不只是首末与总额。

这类断言现在加进了测试。也许该把它做成 `compute_metrics` 的一部分——
当某根收益率的绝对值超过 50% 时，在 `warnings` 里提示"数据或计算可能有误"。
列入后续。
