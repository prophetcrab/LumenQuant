# 迭代记录 C73：让异常权益跳变自己暴露

## 动机

C72 的根因是权益漏算在途资金，但真正让它藏了这么久的是**指标口径**：

`total_return_pct` 只看首末两点。一条在第 150 根塌陷 95%、第 151 根复原的曲线，
在它看来与一条平顺曲线完全一样。回撤、Sharpe 会变形，但不会指向"这里有问题"。

所以 C72 的文档写了：应当把"单根收益率是否合理"变成自动检查。

## 实现

回测末尾扫描逐根收益率：

```python
IMPLAUSIBLE_BAR_RETURN = 0.50

def _extreme_bar_return(equity):
    for index in range(1, len(equity)):
        change = (equity[index] - equity[index - 1]) / equity[index - 1]
        if abs(change) >= IMPLAUSIBLE_BAR_RETURN:
            return index, change * 100
    return None
```

触发时写入 `warnings`：

> 第 151 根 K 线的权益变动 -94.7%，超出正常价格波动范围；
> 可能是数据缺口或资金计算错误，请核对后再使用该结果

### 阈值为什么是 50%

在只做多、有现金账户的模型里，单根权益变动最多来自"仓位比例 × 价格变动"。
即使满仓、即使遇到 A 股跌停（-10%），也不会到 50%。

放宽到 50% 是为了容纳：

- 加密的极端插针（单根 30%+ 确实存在）
- 开盘跳空（前收盘与今开的巨大缺口）
- 数据缺口导致的跨日聚合

同时仍能抓住 C72 那种 -95% 的资金账务错误。

## 实测

| 场景 | 单根最大变动 | 是否告警 |
|---|---|---|
| 真实 A 股三标的篮子（400 根日线） | +2.5% / -2.25% | 否 |
| 修复前的 C72 缺陷 | +1785% / -94.7% | 是 |
| 平盘序列 + 50% 仓位 | ~0% | 否 |

真实数据与平盘数据都不误报。

## 设计取舍

- **为什么放进 `warnings` 而不是抛异常**：这是"结果可疑"，不是"计算失败"。
  用户可能确实在用一份有缺口的第三方数据，他需要看到结果并知道风险，
  而不是拿不到结果。
- **为什么只报第一处**：多处异常通常源于同一个根因。列出 20 条相同的警告
  只会稀释注意力。修掉根因后重新跑即可。
- **为什么阈值是常量而不是配置**：一个可以随意调高的检查等于没有检查。
  如果确实需要放宽（比如研究极高杠杆品种），应当在代码里显式改并留下记录。
- **为什么在引擎里而不是在 `compute_metrics` 里**：`compute_metrics` 是纯函数，
  输入只有权益数组；它不知道这个数组是否经过结算、是否有资金转移。
  引擎知道自己的资金流，判断更准确。
