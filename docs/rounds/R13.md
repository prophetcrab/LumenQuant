# R13 组合分析

## 需求设计
让权益曲线“自己长出来”，并给出可解释的风险收益统计与归因：
- 后台定时记录权益快照，不依赖用户是否打开页面；
- 基于快照收益计算波动、Sharpe/Sortino（按样本，不伪造年化）、正收益比例、盈亏因子、最值；
- 按标的汇总浮盈/已实现/合计盈亏；
- 快照同时喂给 R12 的熔断基准。

## 代码编写
- `portfolio/engine.py`：15 秒循环，遍历活跃账户记录快照并评估熔断。
- `portfolio/service.py::analytics()`：回撤与持续期、收益统计、归因。
- `GET /api/portfolio/analytics`。
- 前端组合页新增 4 个统计卡与“盈亏归因”表。

## 代码审查
1. 年化指标容易误导：快照间隔受节流影响，不固定为日频 → 明示 `*_per_sample`，不做假年化（语义修正）。
2. 快照循环会与 API 请求并发写 SQLite → 依赖 WAL + busy_timeout，且单次事务短（已具备）。
3. 归因只统计当前持仓 + 该持仓的已实现盈亏，平仓后从持仓表消失的标的不会出现在归因里 → 记录为已知限制，R16 数据层可扩展成按成交流水归因。
4. 熔断评估放到后台后，用户不打开页面也能在亏损触线时自动停止新开仓（设计完善）。
