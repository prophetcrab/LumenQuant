# 迭代记录 C19：真实行情下的交易闭环

## 目的

C17/C18 验证了"能取到真实数据、口径正确"。本轮验证：**这些真实数据进入
交易链路后，A 股规则是否仍然成立**。

## 完整闭环验证（真实数据，平安银行 11.29）

```
账户: 人民币账户，初始 300,000
标的: 000001.SZ 平安银行，现价 11.29，涨跌停 [10.30, 12.58]

买入 1000 股 @ 11.29（限价 11.35 立即成交）
  → 成交价 11.29，手续费 5.11（最低佣金生效）

持仓: 1000 股，可用 0        ← T+1 冻结
当日卖出 → 409「可用数量不足：可卖 0 股（T+1 当日买入次日可用）」

结算后: 可用 1000
卖出 1000 股 → 成交，手续费 10.77

费用对比: 买入 5.11 / 卖出 10.77   → 印花税确实只在卖出时收取
权益恒等式: 现金 + 持仓市值 - 权益 = 0.0
组合收益: +0.0014%（仅手续费损耗，符合预期）
```

## 关键确认

| 规则 | 真实数据下表现 |
|---|---|
| 涨跌停 | 区间基于真实昨收 11.29 计算，买入未被误拦 |
| 手数 | 1000 股为 100 整数倍 |
| T+1 | 当日卖出被拒，结算后解锁 |
| 费用 | 买卖不对称，卖出含印花税 |
| 权益守恒 | delta = 0.0 |

## 与前几轮的区别

之前所有交易测试都跑在**合成数据**上。合成数据的价格水平与真实市场不同，
但交易规则与数据来源无关，所以这一轮的价值在于确认：

- 真实报价能在成交价、费用计算、持仓成本中正确流动；
- 涨跌停区间用真实昨收而非合成初值时，边界判断依然正确；
- 没有因为价格小数位（11.29 vs 1680.00）导致精度问题。

## 顺带发现并修复的脚本问题

验证脚本里 `get()` 只返回 payload 不返回状态码，导致
`positions` 解析报 `ValueError`。这是**探测脚本**的缺陷，不是产品缺陷，
但值得记录：验证脚本本身也可能骗人，看到异常先确认是脚本还是系统的问题。
