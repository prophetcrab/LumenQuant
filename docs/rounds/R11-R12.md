# R11–R12 实盘适配器与风控升级

## R11 需求设计
在不污染模拟路径的前提下接入真实交易所：抽象 `BrokerPort`，实现 Binance 现货 REST（HMAC 签名）；
实盘需服务端开关 + 密钥双重就绪；密钥仅来自环境变量，不落库、不返前端。

## R11 代码编写
- `brokers/base.py`：`BrokerOrderRequest/Result`、`BrokerAccount`、`BrokerPort`。
- `brokers/binance.py`：`/api/v3/account`、`/api/v3/order`（市价/限价 GTC）、撤单、挂单查询；状态映射到本系统状态机。
- `brokers/router.py`：`/status`、`/verify`。
- 测试使用 `httpx.MockTransport`，不触网。

## R11 代码审查
1. 签名参数必须用“未编码的原始查询串”参与 HMAC，再整体编码 → 先 `urlencode` 再加签名，测试用独立重建校验（已覆盖）。
2. 401/403 统一映射为“凭据被拒绝”，避免把密钥错误误报成系统故障。
3. 限价单缺少价格时在发请求前拒绝，节省一次无效调用。
4. `build_broker` 在开关关闭或无密钥时返回 None，调用方必须显式处理。

## R12 需求设计
账户级熔断：日损失、峰值回撤；单笔/持仓/频率/最小金额限额；熔断后禁止新开仓、可直接放行平仓逻辑之外的查询；
提供状态查询与人工重置。所有阈值可由环境变量配置。

## R12 代码编写
- `risk/policy.py`：新增 `RiskLimits` 的日损失/回撤字段、`RiskContext` 权益字段、`breaker()`、`check()`。
- `risk/service.py` + `models.py`：`risk_states` 表，记录日内基准与峰值，熔断原因，重置。
- `trading/service.py`：下单前先查熔断，再走限额校验；触发时写审计。
- `risk/router.py`：`/limits`、`/state`、`/observe`、`/reset`。
- 前端 `RiskPanel` 嵌入组合页。

## 代码审查（缺陷与修复）
1. 熔断状态若只在内存，重启即失效 → 落库（设计完善）。
2. `RiskContext` 新增字段带默认值，避免破坏既有调用与测试。
3. 平仓不受“禁止开仓”影响：卖出校验仍走持仓检查，不会误伤减仓（语义正确）。
