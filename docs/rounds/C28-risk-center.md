# 迭代记录 C28：风险中心页面

## 动机

盘点前端页面时发现一个结构性缺口：`risk` 有组件（RiskPanel）但没有独立页面，
风控信息只能从组合页底部间接看到。而 C27 刚把止损变成核心能力——
"哪些实例没有保护"这类信息没有任何地方可以集中查看。

## 后端：一个聚合接口

`GET /api/risk/overview?account_id=`

一次返回完整风险快照，避免前端并发拉五个接口再拼：

| 区块 | 内容 |
|---|---|
| `account` | 名称、市场、计价货币、类型 |
| `state` | 熔断状态、日内基准、峰值、基准日 |
| `limits` | 单笔/持仓/最小金额/频率/日损失/回撤 |
| `exposure` | 权益、账面现金、可用现金、冻结、持仓市值、敞口、最大单一持仓 |
| `positions` | 逐标的持仓、成本、现价、浮盈率 |
| `instances` | 每个自动运行实例的止损/止盈/移动止损/峰值/执行数/错误 |
| `warnings` | 运行中但未设任何止损的实例名单 |

**服务端一次事务内取数**，保证页面上的数字互相自洽（不会出现"权益按旧值、持仓按新值"）。

## 前端：独立风控页

新增 `/risk` 路由与侧栏入口（盾牌图标，置于研究分组）。

页面结构：

1. **顶部四卡**：交易闸门 / 当前敞口 / 可用与冻结现金 / 受保护实例比例
2. **红色告警条**：只要存在"运行中但无止损"的实例就显示，逐条点名
3. **账户级熔断**：日内基准、历史峰值、当前权益、两条限额、重置按钮
4. **下单限额**：服务端强制参数，说明实例级配置叠加生效
5. **持仓风险**：含 **3% 止损参考价**列（`成本 × 0.97`），给用户一个直观的止损位参考
6. **自动运行保护状态**：未设止损的行用红色标注"未设"
7. **资金占用**：账面 / 冻结 / 可用 / 持仓市值四项并列

## 设计取舍

- **为什么在页面上算 3% 止损参考价**：实例的止损是各自配置的，而手动持仓没有止损概念。
  给一个统一参考值（3% 是常见起点）比留空更有用，且明确标注为"参考"。
- **为什么告警放在最顶部**：这是唯一需要用户*立即行动*的信息；
  其余都是观察性数据。
