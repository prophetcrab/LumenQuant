# 迭代记录 C40：实盘开户入口与前端风险提示

## 动机

C39 修了一个严重后端缺陷：实盘自动运行可以绕过确认头。修完之后验证前端时发现一个更基础的问题：
**前端根本没有创建实盘账户的入口。**

`api.createAccount` 的类型签名里有 `kind?: "paper" | "live"`，但创建对话框从来不传这个字段，
所以界面上只能创建模拟账户。实盘账户只能靠直接调 API 创建——文档里描述的实盘流程在 UI 上走不通。

这也解释了为什么 C39 的缺陷一直没被使用者发现：没有人能从界面进入实盘。

## 实现

### 账户类型选择

创建对话框新增"账户类型"下拉：

- 模拟（不接触真实资金）
- 实盘（真实资金）

选择实盘时：

1. **标题变为"创建实盘账户"**，按钮也从 `primary` 变成 `danger`（红色）
2. **隐藏杠杆**：实盘走券商，杠杆由券商决定，本地设置没有意义
3. **资金字段的说明改为**"实盘账户的现金以券商为准，此值仅作本地记账初始基准"
4. **显示风险区块**（红底）：
   - "实盘账户会产生真实资金变动。"
   - 手动下单仍需要 `X-Live-Confirm: true`
   - 自动下单还需要 `LQ_LIVE_AUTO_TRADING_ENABLED`
   - "本项目用于研究与教学，不构成投资建议。实盘交易可能导致资金损失。"

### 自动运行页的实盘提示

创建实例的对话框在账户为实盘时显示同类警示，明确说明：

- 此实例会自动下真实订单
- 需要服务端开启 `LQ_LIVE_AUTO_TRADING_ENABLED`
- 关闭该开关后已存在的实例会立即停止**开仓**，但止损等保护性离场不受影响

最后一点很重要：如果用户以为关掉开关会连止损一起停，他可能会在持仓时犹豫要不要关，
反而让仓位暴露更久。

## 设计取舍

- **为什么不用打字确认（type-to-confirm）**：实盘账户创建本身不产生资金变动，
  真正的风险动作是下单。把摩擦放在正确的位置——下实盘单需要确认头，
  自动运行需要独立开关——比在开户时要求输入账户名更有效，也不会让用户对弹窗麻木。
- **为什么把风险提示做成常显区块而不是一次性 toast**：toast 会消失，
  而这个对话框可能开着很久（用户在填资金）。
- **为什么保留模拟账户为默认**：绝大多数使用场景是研究。默认安全。

## 安全边界（完整表述）

真实资金变动需要同时满足：

| 动作 | 条件 |
|---|---|
| 创建实盘账户 | `LQ_LIVE_TRADING_ENABLED=true` + 界面选择"实盘" |
| 手动实盘下单 | 以上 + 网关 ready + 请求头 `X-Live-Confirm: true` |
| 自动实盘下单 | 以上 + `LQ_LIVE_AUTO_TRADING_ENABLED=true`（每次调度复查） |

密钥只从环境读取，不写入数据库。同花顺集成仍限定为授权的 HTTP 下单网关，
不驱动桌面客户端、不注入窗口句柄、不模拟键鼠、不读取进程内存。

## 后续

- 实盘账户目前与模拟账户共用同一套账本。真实场景下本地现金余额会与券商不一致，
  对账依赖 `POST /api/brokers/ths/reconcile`。可以加一个"账实差异"指标挂在风险中心。
- 开户表单可以增加"我已阅读并理解风险"复选框，作为更明确的一次性确认。
