# 迭代记录 C21：数据卫生与同步健壮性

## 验证内容

真实数据接入后，连续对同一标的同步 3 次，然后检查数据质量与错误路径。

## 发现的问题

### 1. `stale_days` 出现负数（-1）

```
000001.SZ  stale_days: -1
```

`staleness_days()` 用"今天 − 最新日线日期"计算天数。出现负数说明最新日线
被判定为**未来**。

原因：库里残留了修复前同步的异常行，加上日期比较未做下界保护。
一条未来日期的数据会让 `stale_days > N` 这类判断全部失效（负数永远不满足）。

修复：`max(0, age)`，并在同步时过滤非交易日。

### 2. 上游可能返回非交易日数据

腾讯日线接口在测试中返回过周日（`2026-10-18`）的行。
若不做过滤，日历会出现空洞，任何"相邻两根日线之差"的计算都会失真。

修复：`_upsert()` 对 `1d` 序列过滤 `is_trading_day(day_key(...))`。

> 备注：排查过程中我一度以为库里也有周日数据，实际是显示脚本用 UTC 转换
> 造成的错觉——北京时间周二 00:00 在 UTC 是周一 16:00。清理脚本删除了 0 行，
> 说明数据本身是干净的。这提醒：**验证工具本身也要验证**。
