# 迭代记录 C92：选股标的"加入"后不可用

## 缺陷

C90 的 `POST /screener/add-symbol` 只把代码写进目录，不拉数据。实测加入
600000.SH 之后：

```
目录行: price=1.0  prev_close=1.0  limit_up=1.1  limit_down=0.9   ← 真实股价 ≈9.5
回测:   422 数据不足：仅有 0 根 K 线，需要至少 34 根
```

两个问题叠在一起：

1. `initial_price=1.0` 是个占位值，但它直接进了列表的现价与涨跌停计算。
   界面上这支股票显示"1.00 元、涨跌停 0.9–1.1"，与真实价格差十倍。
2. 没有 K 线，回测、图表、自动运行全部不可用。

接口返回的是 `201 created: true`，提示"已加入标的列表，请同步历史数据"——
一个**看起来成功、实际不能用**的状态。用户还得自己去 A 股页找到同步按钮，
而且不知道要同步哪一个（那里默认同步全部标的）。

## 修复

`add-symbol` 默认在注册后立即导入该标的的历史：

```python
def add_symbol(..., sync: bool = True):
    ...
    if sync and settings.cn_data_source != "synthetic":
        report = CnDataSyncService(session, TencentSource(...)).sync_symbols([code], ...)
```

返回值带上实际结果，而不是笼统的"已加入"：

```json
{"created": true, "symbol": "600000.SH", "name": "浦发银行",
 "synced": true, "daily_bars": 800, "intraday_bars": 320,
 "detail": "已加入标的并导入 800 根日线、320 根 15 分钟线"}
```

### 三种必须区分的结果

| 情况 | `synced` | detail |
|---|---|---|
| 导入成功 | `true` | 已加入标的并导入 N 根日线、M 根 15 分钟线 |
| 上游失败 | `false` | 已加入标的，但历史同步失败：<原因> |
| 合成模式 | `false` | 已加入标的列表（合成模式没有可同步的数据源） |

上游失败时**保留已注册的标的**：让用户重试同步即可，把目录行删掉会迫使他们
重新走一遍筛选。

合成模式单独说明，因为"没有可同步的数据源"和"同步失败了"是完全不同的原因，
混在一起会让人去排查网络。

### `sync=false` 保留

批量把十几个候选加入目录、之后再一次性同步，是合理的工作流。这个参数让
它可以继续存在，只是不再是默认。

## 验证

真实腾讯数据（600000.SH，目录中原本不存在）：

```
add: 201 {'created': True, 'synced': True, 'daily_bars': 800, 'intraday_bars': 320,
          'detail': '已加入标的并导入 800 根日线、320 根 15 分钟线'}
catalog: price=9.53  prev_close=9.62  limit_up=10.58  limit_down=8.66
backtest: 201  return=-11.51%
```

价格与涨跌停恢复正常，回测直接可用。

测试覆盖两条路径：导入成功（断言 `synced`、至少 10 根日线、涨跌停包住现价）
与 `sync=false`（断言 `synced: false` 且提示同步）。

## 回归

- 后端 **519 passed**（新增 2 项）
- 前端 66 passed，`tsc` 干净，构建通过

## 已知限制

1. **单标的同步是串行的**：一次只导入一个代码。批量导入仍应走
   `/api/cn/data/sync`。
2. **失败不回滚注册**：目录行保留，靠下一次同步补数据；若代码本身写错，
   需要手动删除。
3. **合成模式无意义**：合成引擎不识别目录中新增的标的，此时加入只是登记。
