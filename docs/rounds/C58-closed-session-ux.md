# 迭代记录 C58：休市时的下单语义

## 动机

A 股每周有 105 小时不在交易时段。用户在晚上或周末打开「交易」页时，
看到的是"休市"两个字，然后一个仍然可点的买入按钮。

点下去会发生什么？页面上没有任何说明。

## 实际行为

后端的分支是：

```python
if not (live and self.cn_live_session_gate) and not self.cn_session_enforced:
    return          # 不检查时段
if not is_session_open():
    raise ConflictError("A股非交易时段，无法下单")
```

默认配置下 `cn_session_enforced=False`，所以：

- **模拟账户**：休市时照常下单，按最近价格即时成交
- **实盘账户**：`cn_live_session_gate` 默认 `True`，休市时被拒绝

这个设计是合理的——模拟盘要能随时做研究，而实盘必须尊重真实时段。
但**界面上完全看不出这个区别**。合理的猜测有三种，都是错的：

1. "现在不能下单"（按钮是灰的？其实可点）
2. "单子会排队到开盘"（没有排队机制，是立即成交）
3. "只有实盘能下、模拟不行"（恰好相反）

## 修法

休市时在下单表单顶部显示一条说明：

> 当前休市。模拟账户仍可下单，按最近价格即时成交；实盘会被交易时段校验拒绝。

一句话把三种猜测都否定掉，且说明了两种账户的差异。

放在表单内部而不是页面顶部：用户在点按钮时一定会看到它，
而页面顶部的横幅在滚动后可能不在视野里。

## 设计取舍

- **为什么不在休市时禁用按钮**：模拟盘休市可交易是刻意的设计。
  禁用会剥夺"晚上研究策略"这个主要用途。
- **为什么不用 toast 提示**：toast 只在下单后出现，而用户需要的是
  **下单前**知道会发生什么。
- **为什么只对 A 股显示**：加密是 24/7，没有休市概念。
- **为什么文案强调"按最近价格"**：这是休市成交最反直觉的一点——
  没有实时行情，用的是最后一根 K 线的收盘价。
