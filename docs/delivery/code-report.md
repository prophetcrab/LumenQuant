## 架构评估

**优点**
1. 模块边界经得起检查：`trading` 不导入 `accounts`/`market` 的模型，只依赖 Protocol。
2. 资金模型无可漂移状态：现金永远是账本求和。
3. 策略是纯函数插件，同一份代码同时服务信号预览、回测与自动交易，避免“三套逻辑”。
4. 失败面收敛：LLM 不可用降级本地、Broker 缺密钥 403、熔断落库、单实例异常隔离。

**债务与改进方向**

| 项 | 影响 | 建议 |
|---|---|---|
| 三个 router 重复装配 Service | 可读性 | 保留（见架构文档“允许的重复”），或引入轻量 DI 容器 |
| 无正式迁移工具 | 破坏性变更受限 | 引入 Alembic |
| 单机限流/指标 | 多进程失效 | 换 Redis + Prometheus |
| 仅多头现货 | 策略表达受限 | 引入持仓方向枚举与保证金模型 |
| 归因不含已平仓标的 | 归因不完整 | 基于成交流水重算 |
| 前端无自动化测试 | 回归靠人工 | 加 Playwright 冒烟用例 |
