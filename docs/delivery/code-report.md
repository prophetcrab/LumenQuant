## 架构评估

**优点**
1. 模块边界经得起检查：`trading` 不导入 `accounts`/`market` 的模型，只依赖 Protocol。
2. 资金模型无可漂移状态：现金永远是账本求和。
3. 策略是纯函数插件，同一份代码同时服务信号预览、回测与自动交易，避免“三套逻辑”。
4. 失败面收敛：LLM 不可用降级本地、Broker 缺密钥 403、熔断落库、单实例异常隔离。

**债务与改进方向**

| 项 | 影响 | 建议 |
|---|---|---|
| 三个 router 重复装配 Service | 可读性 | 保留（见架构文档“允许的重复”），或引入轻量 DI 容器 |
| 无正式迁移工具 | 破坏性变更受限 | 引入 Alembic |
| 单机限流/指标 | 多进程失效 | 换 Redis + Prometheus |
| 仅多头现货 | 策略表达受限 | 引入持仓方向枚举与保证金模型 |
| 归因不含已平仓标的 | 归因不完整 | 基于成交流水重算 |
| 前端无自动化测试 | 回归靠人工 | **已解决**：Vitest + Testing Library，48 项 |

## 安全清单

- [x] 实盘默认关闭，需开关 + 密钥 + 确认头三重条件（手动下单）
- [x] 自动实盘下单需独立的 `LQ_LIVE_AUTO_TRADING_ENABLED`，且每次调度复查
- [x] 关闭自动开关不影响止损等保护性离场（避免"关掉保护"的反向风险）
- [x] 归档账户会停止其上所有运行中实例，执行时再复查一次
- [x] 密钥只从环境读取，不写入数据库
- [x] 同花顺集成限定为授权 HTTP 网关：不驱动客户端、不注入窗口句柄、不模拟键鼠
- [x] 密钥仅环境变量，不落库、不返前端
- [x] 可选 Bearer 认证，健康检查公开
- [x] 固定窗口限流，429 带 `Retry-After`
- [x] 令牌恒定时间比较
- [x] 所有写操作审计留痕
- [x] CSV 导入大小/编码/OHLC 校验
- [x] 前端不存令牌，实盘提示常驻
- [ ] 未做多用户权限与租户隔离（单用户设计）
