# 架构思路

## 目标与约束

1. 功能覆盖账户、模拟/实盘、行情、策略、回测、可视化、AI 助手。
2. 后端最低耦合：允许少量重复代码，换取模块边界清晰。
3. 可扩展：新增策略、交易所、行情源、AI 提供方均不改核心引擎。
4. 2K 屏幕优先：2560×1440 下信息密度高、层级清楚，浅色极简。

## 总体形态

采用**模块化单体**而非微服务：个人交易平台的数据一致性、部署成本与调试效率优先。
每个模块是一个 bounded context，拥有自己的表、服务与路由；跨模块只允许三种通道：

- **同步端口**：消费方定义 `Protocol`（如 `AccountReader`），由组合根注入实现。
- **领域事件**：`OrderFilled` 等事实通过进程内 EventBus 广播，发布方不认识订阅方。
- **只读查询**：看板类聚合由 `portfolio` 编排多个读端口，不直接 JOIN 他模块表。

禁止：跨模块导入 ORM 模型、跨模块写表、在路由里写业务逻辑。

## 模块划分

| 模块 | 职责 | 依赖方向 |
|---|---|---|
| accounts | 账户生命周期、资金账本 | core |
| market | 标的目录、K 线、行情源 | core |
| trading | 订单、撮合、持仓、成交 | accounts/market 端口、risk 端口 |
| risk | 下单前校验、限额、熔断 | 无（纯计算） |
| strategies | 策略插件、参数模型、信号 | market 数据（输入） |
| backtest | 事件驱动回测、绩效指标 | strategies、market 端口 |
| runtime | 策略实例调度、行情推进、快照 | 上述端口 |
| portfolio | 组合视图、权益曲线、分析 | 读端口 |
| assistant | 工具注册、会话、LLM 适配 | 读端口 |

## 数据与交易模型

- 账户现金由**只增不改的账本**求和得出，任何资金变动都有流水。
- 持仓用带符号数量表示（正多负空），均价、已实现盈亏随成交更新。
- 订单状态机：`new → open → partially_filled/filled/cancelled/rejected`。
- 回测遵循「收盘出信号、下一根开盘成交」，计手续费与滑点，避免未来函数。
- 行情默认由确定性合成器生成（含趋势/震荡切换），支持 CSV 导入替换。

## 前端结构

`features/*` 按业务域切分，`shared/*` 放 API 客户端、格式化与基础组件。
布局以 12 栅格 + 固定侧栏组织，卡片圆角 14px、1px 边框、柔和阴影；
颜色以中性灰为底、单一靛蓝强调色，涨跌使用低饱和绿/红，避免霓虹暗色风。

## 关键决策

- **SQLite 起步**：零运维；通过 SQLAlchemy 保持迁移到 PostgreSQL 的可能。
- **同步服务层**：撮合/回测是 CPU 任务，避免 async 染色；FastAPI 用线程池承载。
- **参数即 Schema**：策略参数用 Pydantic 模型声明，前端动态表单和后端校验共用一份定义。
- **实盘隔离**：交易所适配器实现 `BrokerPort`，默认关闭；密钥只从环境读取，不落库。
